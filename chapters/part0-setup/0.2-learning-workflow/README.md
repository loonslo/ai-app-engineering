# 0.2 学习方法与验收记录

[全书目录](../../README.md) · [上一章 L0.1](../0.1-environment/README.md) · [下一章 L0.3](../0.3-coding-agent-workflow/README.md)

- **目标**：每章结束时留下“我改了什么、哪条证据证明它、还不能证明什么”。
- **v3 路径**：L0.2 / 核心（清单验收）
- **岗位任务 / 面试题型**：T4、T7 / F6
- **前置**：0.1。
- **环境**：无需运行代码。

## 问题

读懂一个脚本，和能独立完成一个功能之间还有距离。你可以复述 RAG 的定义，却说不清答错时该先查检索还是生成。本章建立一种记录方式，让每章都留下自己的理解和可定位的证据。

## 概念

- **问题**：这个功能为什么存在。
- **流程**：数据依次经过哪些步骤。
- **验收**：能证明行为的观察或测试。教程里的完成版代码只是参考实现，个人是否学会由自己的练习和结果决定。

## 一次练习的六步

1. 从 [章节总地图](../../README.md) 选一章，先读目标、输入与失败边界。
2. 沿正式入口画出调用链：输入 → 数据 / 模型 / 工具 → 输出，不要只看新增文件。
3. 先运行已有例子或相关测试，记录基线与执行环境。
4. 提出一个可验证的假设，只改一处实现或输入，再观察结果。
5. 加一个有意义的失败实验，证明系统知道何时拒答、失败或停止。
6. 保存命令、退出码、证据位置与限制，再更新任务状态。

不同主题要观察的对象不同：

- RAG：来源、切分、召回、重排、上下文、生成、引用，分别观察。
- Agent：状态、节点、边、工具副作用、最大步数、终止原因。
- 测试替身固定输出，适合验证业务规则；真实模型评测还要关注样本、版本、质量和成本。

## 三条运行路线

| 路线 | 从哪里运行 | 证明什么 |
|---|---|---|
| 独立章节 | 根目录 `python tools/run_chapter.py 2.4` | 这一节的局部规则与输出 |
| 旗舰项目教学快照 | `tools/materialize.py` 还原后，运行累计测试 | 当前步骤与此前能力的集成 |
| capstone 整合实现 | 根目录 `python -m pytest capstone/test_production.py -q` | capstone 的离线生产边界 |

旗舰项目快照和 capstone 入口不同，一套通过的测试不能替另一套背书。真实模型回归见 `capstone/test_regression.py`，运行前确认本机配置、评测资料和外部调用范围。

## 作品证据怎么积累

求职和面试只认事实证据。阅读完 README、代码文件存在或 git 提交记录不是能力的证明。本课程中产出的所有成果划分为三类证据，每一类回答不同的工程问题，且直接对应 [大纲出口标准（E1–E4）](../../../docs/v3/outline.md#6-就业出口标准e1e4)：

### 三类证据的定义与分工

| 类别 | 运行环境 | 证明什么 | 对应出口 |
|---|---|---|---|
| **离线 gate** | 离线替身、假模型、固定数据、本地 pytest | 本地状态机转移、重试/限流控制流、数据校验契约、错误注入恢复逻辑符合预期 | **E3**（Take-home 与编码面试）、**E2**（功能实现基线） |
| **真实运行** | 真实 LLM API、本地真实 Embedding/Reranker、向量数据库 | 真实模型的输出质量、Token 成本计算、p95 延迟、Prompt A/B 判定效果、Golden Set 评测准确率与混淆矩阵 | **E1**（真实评测报告）、**E2**（评测长文）、**E3**（评测讨论） |
| **部署** | 容器（Docker Compose）、云 VPS、HTTPS 外网访问 | 真实网络可用性、生产级鉴权与限流、日志脱敏与计费上限、真实用户请求收集、监控告警与故障事故复盘 | **E1**（主作品：≥4 周、≥5 真实用户、≥200 次请求、事故复盘） |

### 证据索引文件的格式

在自己的作品目录或独立项目根目录下建立一份持久的 `EVIDENCE.md` 索引文件，每完成一处有价值的验证即登记一条，格式如下：

```markdown
| 证据编号 | 证据名称 | 验证命令 / 文件路径 | 验证日期 | 证据类型 | 对应标准 | 实际结论与未验证项 |
|---|---|---|---|---|---|---|
| EV-01 | L0.4 工程底座 Gate | `python chapters/part0-setup/0.4-python-engineering-base/gate/gate_check.py` | 2026-10-27 | 离线 gate | E3 | 12 项注入检查全部 PASS；未验证真实外部网络 |
| EV-02 | L1.10 嵌入式分类 Eval | `python chapters/part1-foundations/1.10-embedded-llm-feature/eval_golden.py` | 2026-10-28 | 真实运行 | E2 | 50 题准确率 94%，平均延迟 420ms；未配置跨地区容灾 |
| EV-03 | P2 最小上线部署记录 | `curl -fsS https://my-app.example.com/health` | 2026-11-05 | 部署 | E1 | HTTPS+Token 鉴权通，收集到 12 次真实请求；暂未接入 OTel |
```

简历与面试中的每一句 STAR 论述、数字指标（如“召回率提升至 92%”、“p95 延迟控制在 1.8s”），都必须能精准追溯到该索引文件中的某一条证据记录。

## 练习：做一份可复查的记录

1. 运行 0.1 自检，把结果写进 [学习记录](workbook.md) 作为基线。
2. 提出假设：“错误引用应该被拒绝”。到 2.4 时，删去引用或改成不存在的片段 ID，确认引用检查失败，同时观察答案关键词仍可能通过。
3. 记录里不写密钥、token 或真实客户数据；不因为目录存在就写“已完成”。

## 验收

另一位读者只凭你的记录就能重跑实验，并区分观察到的事实和推测的原因。回答：哪条测试覆盖失败路径？哪一项仍需要真实模型？出问题时如何恢复自己的修改？

## 边界

模板只是记录工具，内容要靠实际运行填写。课程文件存在，不代表你已学完；离线测试通过，也不能代替真实模型或部署验收。
