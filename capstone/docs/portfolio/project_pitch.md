# 5 分钟项目讲解（里程碑 7.6 / step2）

> 原则：只讲仓库和报告能证明的事实。括号里的“边界”也要主动说，它比夸大数字更能体现工程判断。

## 0:00–0:30：定位与差异化

我做的是一个企业知识库问答与自动化评测平台。重点不是聊天界面，而是把检索、权限、回归、安全、高并发稳定性和运行指标放到同一条可验证链路里。这延续了我的测试工程背景：把概率性模型能力转成有边界、有失败信号、多租户安全的确定性系统。

## 0:30–1:40：数据、问答和权限闭环

数据层支持 TXT、Markdown 和 PDF。文档经过确定性切分后同时进入向量检索与 BM25，两路结果做融合；应用只根据真实召回文档生成来源，避免模型自己编造文件名。

文档变化通过 SHA-256 manifest 做增量同步，新增、修改、删除只处理差异，确定性 chunk ID 保证全量构建和增量构建完全一致。

企业数据不能只靠 Prompt 保密。当前实现会在向量查询发出前带上 ACL 过滤，BM25 也只看授权子集；租户有独立持久化目录，JWT claims 提供用户、租户、部门和角色。测试覆盖默认拒绝、跨租户拒绝和查询前过滤。针对跨租户串用，我们设计了包含租户、用户角色和知识版本的 TTL 缓存，知识库一旦更新旧缓存即刻失效。

## 1:40–2:50：评测金字塔与 CI 门禁

我把评测集作为版本化回归输入。针对大模型输出的随机性，CI 阶段采用规则断言执行“黄金用例集回归”：应拒答的超纲问题必须精准拒答且无引用，事实问题必须命中核心关键词且引用真实召回。2026-07-29 用本地配置的 DeepSeek 实跑结果是关键词命中 4/4、拒答 2/2、失败 0。

我会明确说明这个数字的边界：它证明当前 6 条回归没有退化，不代表真实业务总体准确率。线上 Bad Case 产生时，我们按“源头→切分→召回→重排→上下文预算→生成→引用”七阶段漏斗排查最早丢失事实的环节，杜绝盲目调优 Prompt 并沉淀为回归用例。

GitHub Actions 会运行生产边界测试、真实模型回归和质量门禁，失败时上传报告。要真正阻止合并，还要在仓库设置里把该检查设为 required。

## 2:50–4:00：服务化、并发调优与可观测性

FastAPI 接口包含 Bearer 认证、租户限流、请求 ID、输入边界与响应脱敏；模型调用、检索、工具调用各有一个 OpenTelemetry span（默认不导出、不采集正文）。另有一个零依赖的静态演示页（`/ui`），展示引用、降级与“需要人工审批”状态，并能提交“有用 / 没用”。监控按租户统计 p50/p95/p99、错误率、token、成本和缓存命中率。

针对多租户高并发场景，我们把租户 Registry 粗粒度全局互斥锁重构为**分租户条带锁（Per-tenant Locks）与双重检查**，使重耗时的文档构建并行化，读路径锁争用大幅降低；同时对 BM25 引入 LRU 控顶（Cap 256）消除内存泄漏风险，SQLite 监控指标消除重复 DDL/WAL 开销。2026-10-26 的优化记录里，34 项离线生产测试耗时由 10.14s 降至 6.62s（当时的数据；此后测试已增加，以重新运行为准）。

我还把 Locust 对准当前认证 API。本地冒烟结果证明压测工具链和指标对照可用；生产定容需要更长稳态和逐级加压。仓库已有 Dockerfile 与部署检查，我表述为“具备部署准备”，不宣称“已上线”。

## 4:00–5:00：有界 Agent 与架构演进

Agent 部分是 `capstone/approval.py` 的审批状态机：只读操作受控调度，高危写操作先生成带幂等校验的持久化草稿，经主管一次性核准，并校验租户与角色。LangGraph 版本的人工审批演示在冻结的 `flagship-project/` 快照里，不是 capstone 的运行链路。

当前选择租户独立 Chroma 是为了低成本完成本地闭环；规模、并发或统一运维上升时，已有平滑切向 `pgvector`（PostgreSQL RLS 行级安全 + 分区）的迁移设计。

一句话收尾：我能做的不只是“让模型回答”，而是为身份、知识、模型调用和质量回归建立可测试的边界；哪些已经验证、哪些仍是假设，我都能给出代码与数据证据。

## 可让面试官继续追问的四个硬核点

1. 为什么 ACL 必须在向量查询和 BM25 建索引前生效，缓存键又为什么包含身份与知识版本。
2. 为什么 6/6 通过仍不能说“准确率 100%”，以及如何用七阶段归因漏斗定位线上 Bad Case。
3. 多租户高并发下，为什么选择分租户条带锁而非纯全局锁或无锁，BM25 的 LRU 是如何做版本失效的。
4. 为什么 Agent 高危操作必须做持久化一次性审批状态机，如何杜绝操作重放与跨租户越权。
