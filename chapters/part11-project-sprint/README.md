# 篇 11 · 项目主线（P）

[全书目录](../README.md) · [上一篇 L5](../part5-production/5.1-serve-fastapi/README.md) · 同期的就业轨道见 [篇 12](../part12-job-track/README.md)

从第 5 周起，把各阶段的产出持续并入**同一个公开项目**：第 6 周末前最小上线，之后两次迭代，持续积累真实用量与证据，最后整理成作品叙事。本篇的章节以指南、清单与模板为主，没有 gate。

“你的项目”指本仓库的 `capstone/`，或你自己的公开仓库。涉及 `capstone/` 代码的改动（去掉框架胶水、接入 OpenTelemetry、演示前端）由课程的 V3-9 批次完成；本篇只告诉你怎么规划、怎么记录、怎么验收。

## 出口：E1 主作品

课程大纲（[outline.md 第 6 节](../../docs/v3/outline.md#6-就业出口标准e1e4)）对 E1 的要求如下：

> capstone 或自有项目：公网可访问且已运行 ≥4 周；≥5 个真实用户、≥200 次真实请求（不含自测）；真实模型评测报告（golden set ≥50 条，judge 用 ≥30 条人工标注校准并给出一致率）；≥2 份事故复盘；p95 延迟、单次请求成本、缓存命中率；`DECISIONS.md`；README 分别列出离线、真实、部署三类证据。

这些数值门槛是**建议值**，按实际记录填写，不得估算或虚构。没有真实用户就如实写没有，不要用自己的测试请求充数。

## 与 capstone 的关系

- 你可以直接把 `capstone/` 当作“你的项目”，也可以用自己的仓库；各章的清单对两者都适用。
- 清单里写“本仓库对应 V3-9 的 capstone 改动”的项，在 V3-9 之前 capstone 尚未完成这些改动；这时请照实写“未完成”，不要把别人的设计文档当成你已有的实现。
- `capstone/docs/portfolio/` 里有现成的简历与项目叙事草稿；它们只能引用有证据的数字（见 `capstone/interview_evidence.py` 的严格检查）。

## 三类证据怎么记

课程把所有成果分成三类证据：**离线 gate**、**真实运行**、**部署**。每一类回答的问题不同，不能互相替代；定义、证据编号和索引格式见 [L0.2 学习工作流](../part0-setup/0.2-learning-workflow/README.md)。

本篇用统一的证据索引记录它们（模板在 [11.6](11.6-project-narrative/templates/evidence-index.md)）：每一条写“声明 → 证据文件或命令 → 日期 → 类型”。

- 离线 gate：本地测试、假模型、固定数据；证明业务规则与边界。
- 真实运行：真实模型、真实 embedding、真实评测；证明质量、延迟、成本。
- 部署：公网访问、HTTPS、真实用户请求；证明可用性与采用。

## 通用规则

- **不虚构**：用户、请求数、事故、数字都只写真实发生的；没有就写“未发生 / 未收集”。
- **隐私**：不公开密钥、内部数据、真实用户姓名与联系方式；访谈记录用代号。
- **每个声明都能对上证据**：对不上的就删。
