# 语义化版本 2.0.0 规范概览

语义化版本规定软件版本号必须遵循标准的通用格式：
版本号格式由三部分组成：主版本号.次版本号.修订号，英文写作 MAJOR.MINOR.PATCH。
软件公开发布后必须明确声明公共 API 规范以约束版本变更。

# 版本号递增原则与约束

标准的版本递增规则遵循以下三条核心准则：
1. 主版本号 MAJOR：当进行了不兼容的公共 API 变更时必须递增；
2. 次版本号 MINOR：当以向下兼容方式新增了功能特性时递增；
3. 修订号 PATCH：当以向下兼容方式进行了缺陷修复、Bug 修复时递增。

# 先行版本号与元数据

先行版本号（Pre-release version）可以标注在修订号之后，必须紧跟一个连字符号（-），例如 1.0.0-alpha.1 或 1.0.0-beta.2。
构建元数据（Build metadata）紧跟在版本号或先行版本号后，以加号（+）连接。
先行版本的优先级低于普通版本，版本比较遵循严格的 ASCII 字符排序规则。
