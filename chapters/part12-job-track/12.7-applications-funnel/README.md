# J7 投递与漏斗 · 就业章

[全书目录](../../README.md) · [上一章 J6](../12.6-behavioral-stories/README.md) · [篇首](../README.md) · [回到项目主线 P6](../../part11-project-sprint/11.6-project-narrative/README.md)

- **目标**：建立目标公司清单、投递漏斗与每周复盘，把投递变成可以度量和改进的过程；每次面试后写复盘；用统一维度比较 offer。
- **v3 路径**：J7 / 就业（清单验收）
- **岗位任务 / 面试题型**：T6 / F6
- **节奏**：5 小时，第 15–16 周集中；第 9 周起可以少量投递。
- **前置**：[12.1 三版简历](../12.1-positioning-resume/README.md)、[篇 11 的作品](../../part11-project-sprint/README.md)、[L0.5 岗位地图](../../part0-setup/0.5-job-map-gap/README.md)。

## 为什么

投递不是“发出去等消息”。把它当成一个有转化率的流程：投递 → 回复 → 面试 → offer，每周看哪一步最弱，针对性地改简历、改作品、改准备。

## 步骤

1. **目标公司清单，按岗位类型分组**（至少 30 家）：按 [12.1](../12.1-positioning-resume/README.md) 的三类岗位（AI 应用工程师、AI 评测与质量工程师、FDE 与交付）分组；每家写岗位链接、匹配度、你的切入点（[模板](templates/target-companies.md)）。
2. **内推优先**：经验之谈（不是统计）：有人愿意推荐时，简历通常更容易被看到。写[内推消息](templates/referral-message.md)时说清楚你是谁、对方的岗位为什么适合你、你的证据链接；不要群发，也不要请求对方替你夸大。
3. **漏斗记录**（[模板](templates/funnel-tracker.md)）：每次投递一行，记录日期、渠道、版本、结果；
4. **每周复盘漏斗转化**（[模板](templates/weekly-review.md)）：投递 → 回复 → 面试 → offer 的数量与转化率；样本小的时候看趋势和具体案例，不要被一两个数字吓到或安慰；
5. **每次面试后写复盘**（[模板](templates/interview-debrief.md)）：问了什么、答得怎样、哪里要补、要不要更新简历或作品；
6. **offer 比较的维度**（[模板](templates/offer-compare.md)）：薪酬结构、成长与学习、团队与导师、业务与技术栈、稳定性、地点与工作方式、合规与风险等；先写你自己的权重，再打分。
7. **底线：不在简历与面试中虚构经历或数字。**被问到不会的，如实说不会并说明你会怎么学。

## 常见失败

- 清单只有大公司，每家都投同一版简历；
- 不记录投递，复盘时凭印象；
- 面试后不写复盘，同样的问题答不好两次；
- 只看薪酬比较 offer。

## 边界

- 本章不保证面试与 offer；结果取决于市场、岗位和很多不可控因素。
- 清单里的公司与岗位信息会过期；投递前请到官方招聘页确认岗位仍然开放。
- 模板里没有示例公司名单或示例数据，所有内容都要来自你自己的记录。
