# J4 LLM 系统设计模拟 · 就业章

[全书目录](../../README.md) · [上一章 J3](../12.3-coding-interview/README.md) · [篇首](../README.md) · [下一章 J5](../12.5-take-home-sim/README.md)

- **目标**：用 5 次限时的书面设计模拟，练出能在 45 分钟内讲清需求、容量、架构、评测、成本、失败处理与安全的能力。
- **v3 路径**：J4 / 就业（清单验收）
- **岗位任务 / 面试题型**：T5、T6 / F3、F5
- **节奏**：8 小时，第 6–14 周，隔周一次，共 5 次。
- **前置**：[L5.11 LLM 系统设计](../../part5-production/5.14-llm-system-design/README.md)（答题框架与模板），L3 评测。

## 为什么

系统设计面试考的是你在信息不全时的取舍与表达，只靠读不会提高，需要**限时输出再复盘**。LLM 系统设计里，评测与成本是最容易被忽略的两块：一篇行业博客（《The eval round is the new system design interview》，[链接](https://www.techinterview.org/post/3233476828/llm-eval-prompt-interview-questions)，读取于 2026-10-31）主张评测讨论正在变成独立的一轮。这是博客观点，我们没有找到支持“多数候选人没准备”的统计依据，请当作提醒，不要当结论。

## 模拟流程

1. **计时 45 分钟**：口述或书写都行，书面更便于复盘。每次从 [`prompts.md`](prompts.md) 里选一题，不要提前看追问清单。
2. **按设计文档模板写**：复用 [L5.11 的设计模板](../../part5-production/5.14-llm-system-design/templates/design-doc.md)；**必须覆盖评测计划与成本**。
3. **追问**：写完（或讲完）后，找同行或让 AI 扮演面试官，按该题的追问清单提问；你当场回答并记录。
4. **自评**：用 [L5.11 的评分表](../../part5-production/5.14-llm-system-design/templates/rubric.md)，每个维度写分数和一句证据。
5. **复盘**：用[模拟记录模板](templates/mock-record.md)写：做得好的、遗漏的、下一次要改的一件事。

## 5 次的安排

| 次 | 周次 | 题目 | 重点 |
|---|---|---|---|
| 1 | 第 6 周 | 题 1：带权限与引用的企业文档问答 | 熟悉框架与时间分配 |
| 2 | 第 8 周 | 题 2：3 个内部工具的工单 Agent | 工具权限与防循环 |
| 3 | 第 10 周 | 题 3：通话摘要的评测体系 | 评测设计 |
| 4 | 第 12 周 | 题 4：多租户 LLM 网关 | 成本控制与降级 |
| 5 | 第 14 周 | 题 5：异步长任务调研 Agent | 检查点与审批 |

可以换顺序，但 5 道题都要做。

## 产物与验收

见 [CHECKLIST](gate/CHECKLIST.md)：5 份书面设计与复盘，登记到证据索引。

## 常见失败

- 一上来画架构图，需求和容量一笔带过；
- 评测和成本留到最后 5 分钟；
- 没有失败模式，或只列“可能会出错”而没有降级与恢复；
- 追问时把原设计推翻重来，而不是在原设计上说明取舍；
- 自评打分偏高，没有指向具体证据。

## 边界

- 这是自我训练，没有真实面试官，也没有标准答案；评分表是课程自用的量表，不是任何公司的标准。
- 5 次模拟不能保证面试表现；它训练的是结构化表达与取舍意识。
- 题目是通用场景，不是某家公司的真题。
