1. 编码 Agent 的工作循环：读码 → 计划 → 改码 → 跑测试；常见失败：编造 API、改坏无关代码、测试只覆盖自己写的路径、引入安全问题、悄悄放宽断言。

## L0.4 AI 应用的 Python 工程底座 · 新增 · gate

- **目录**：`chapters/part0-setup/0.4-python-engineering-base/`（新建）
- **课时**：3h（1h 读 + 1.5h 实现 + 0.5h 记录）
- **岗位任务 / 面试题型**：T5、T7 / F1、F4
- **学完能做**：用 Pydantic v2 定义配置与数据契约；写带超时、重试、并发上限的 async 代码；用 httpx 的 `MockTransport` 离线测试 HTTP 客户端。

### README 必讲

1. 类型标注、`dataclass` 与 Pydantic `BaseModel` 的分工：内部数据用 dataclass，边界输入用 Pydantic 校验。
2. Pydantic 的校验错误长什么样，怎样转成对用户可读、不泄露密钥的错误。
3. `async` / `await` 基础、`asyncio.wait_for` 超时、`asyncio.Semaphore` 控制并发。
4. 带退避的重试：只重试可重试的错误；把 `sleep` 当参数注入，测试才不需要真的等待。
5. 用 `httpx.MockTransport` 做离线测试替身——测试背景的人最熟悉的部分，后续 gate 都沿用这个思路。

### 闭卷接口（`gate/starter.py`）

```python
class SettingsError(ValueError): ...
class HttpError(Exception):
    def __init__(self, kind: str): ...   # kind: "status:<code>" | "invalid_json" | "timeout"

class Settings(BaseModel):
    provider: Literal["deepseek", "openai", "openai_compatible", "ollama"]
    model: str            # 去掉首尾空白后不能为空
    timeout_s: float      # 0 < timeout_s <= 120
    max_retries: int      # 0 <= max_retries <= 5

def load_settings(env: Mapping[str, str]) -> Settings:
    """读取 LLM_PROVIDER、MODEL、TIMEOUT_S、MAX_RETRIES。
    校验失败抛 SettingsError，消息列出出错的字段名，不包含任何值。"""

async def retry_async(fn, *, attempts: int, base_delay: float, sleep, retry_on: tuple[type[BaseException], ...]):
    """最多调用 attempts 次；第 i 次失败后等待 base_delay * 2**i（i 从 0 开始），等待通过 sleep 完成；
    只对 retry_on 中的异常重试，其他异常立即抛出；次数用尽时抛出最后一次的异常。attempts < 1 抛 ValueError。"""

async def gather_limited(factories, limit: int) -> list:
    """factories 是返回协程的无参函数列表；同时运行的协程不超过 limit；结果顺序与输入一致；limit < 1 抛 ValueError。"""

async def fetch_json(client: httpx.AsyncClient, url: str, *, timeout_s: float) -> dict:
    """GET url；非 2xx 抛 HttpError("status:<code>")；响应体不是 JSON 对象抛 HttpError("invalid_json")；
    超时（httpx.TimeoutException）抛 HttpError("timeout")。"""
```

### 故障注入与检查（总数 ≥11）

| # | 注入 | 期望 |
|---|---|---|
| 1 | `LLM_PROVIDER=foo` | `SettingsError`，消息含 `provider` |
| 2 | `MODEL` 为空白 | `SettingsError`，消息含 `model` |
| 3 | `TIMEOUT_S=0` 或 `121` | `SettingsError` |
| 4 | 密钥类变量出现在 env 中 | 错误消息不含其值 |
| 5 | fn 先抛两次可重试异常再成功 | 返回成功值；sleep 依次收到 base_delay、2×base_delay |
| 6 | fn 抛不在 retry_on 中的异常 | 立即抛出，不调用 sleep |
| 7 | 次数用尽 | 抛最后一次的异常 |
| 8 | 10 个任务、limit=3 | 任意时刻并发数 ≤3（gate 用计数器测量）；结果顺序正确 |
| 9 | limit=0 | `ValueError` |
| 10 | MockTransport 返回 500 | `HttpError("status:500")` |
| 11 | 返回非 JSON | `HttpError("invalid_json")` |
| 12 | MockTransport 抛 `httpx.ReadTimeout` | `HttpError("timeout")` |
