第 1 讲：怎么正经调一次大模型 API

平时写个脚本玩玩，调大模型无非就是几行代码。但如果在实际做项目、写后端服务时，直接照搬 Demo 写法，很快就会遇到几个麻烦：

接口卡住挂起
网络一抖动或模型稍慢，接口跟着无限等待，最后整条服务崩掉。
回答少半截
长问题只答了一半突然没了，以为答完了，其实是字数超限被系统硬掐断了。
查账两眼摸黑
月底账单超标，却不知道哪个功能花了多少 Token、哪次请求耗时最长。

1. 调 API 时到底传了什么、收了什么？

大模型调用的底层本质就是一个最普通的 HTTP POST 请求：你发给服务商一个 JSON，对方给你回一个 JSON。

发请求时，主要看 messages 里的两个角色：
role: "system"

负责定规矩、立人设。比如“你是一个退货客服，只根据规则回答，不要闲聊”。

role: "user"

用户在聊天框里真实输入的那句话。

* 另外做功能时通常加 temperature=0，让模型输出尽量确定，别变来变去。
收结果时，除了文本内容，盯死这两个字段：
finish_reason（为什么停下）

"stop" 表示正常答完。
"length" 代表碰到了字数限制被截断，前端要提醒用户，别当正常回答展示。

usage（Token 消耗量）

输入 Token（prompt_tokens）与输出 Token（completion_tokens）。输出字数越多不仅越贵，接口耗时也会翻倍。

2. 最干净的代码长什么样？

# 原生 SDK 调用，没有多余包装 import os from openai import OpenAI client = OpenAI( api_key=os.getenv("DEEPSEEK_API_KEY"), base_url=os.getenv("OPENAI_BASE_URL", "https://api.deepseek.com"), ) response = client.chat.completions.create( model="deepseek-flash", messages=[ {"role": "system", "content": "你是一个严谨的技术助手，回答尽量精简。"}, {"role": "user", "content": "用一句话解释什么是检索增强生成（RAG）？"}, ], temperature=0.0, ) choice = response.choices[0] print("回答正文:", choice.message.content) print("结束状态:", choice.finish_reason) print(f"Token 统计: 输入 {response.usage.prompt_tokens}，输出 {response.usage.completion_tokens}")

3. 线上常见报错怎么处理？

错误类型 典型原因 能不能自动重试？ 实际怎么处理？
401 AuthError 密钥填错、没钱了、未授权 ❌ 不能 直接报错，发飞书/钉钉告警通知管理员排查
429 RateLimitError 请求太频繁，超频了 可以 等个 1~2 秒再重新发一次（退避重试）
APITimeoutError 网络慢、丢包、模型卡死 可以 设置超时（如 timeout=15），超时后重发或换备用模型
