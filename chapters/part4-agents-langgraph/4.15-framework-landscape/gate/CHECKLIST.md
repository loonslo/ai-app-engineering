# 4.15 框架取舍 · 清单验收

本章是 L4.16 清单与离线练习，不设可执行 gate，不生成 `gate_report.json`。在 [workbook](../workbook.md) 填写证据，不能只凭框架名或脚本退出 0 勾选。

## 步骤

- [ ] 写一个明确需求与失败标准，说明为什么普通函数够用或不够用。
- [ ] 按同一组维度比较：控制流、预算/停止、可观测、持久化/HITL、部署、学习成本、锁定风险。
- [ ] 矩阵至少包含下表四类，每一行都写“何时选择、本次采用与否、拒绝条件、退出成本”。可增加候选，不能删减四类。

| 必须比较的方案 | 选择条件 / 本次决定 | 拒绝理由 | 退出成本（代码 / 消息 / 状态 / 重验） |
|---|---|---|---|
| 原生 SDK + 自己的循环 | 待填写 | 待填写 | 待填写 |
| Pydantic AI | 待填写 | 待填写 | 待填写 |
| LangChain / LangGraph | 待填写 | 待填写 | 待填写 |
| OpenAI Agents SDK | 待填写 | 待填写 | 待填写 |

- [ ] 说明 LangChain 与 LangGraph 的层次区别，以及 checkpointer、session、持久执行、外部隔离不能互相替代的原因。
- [ ] 标明每项结论来自文档、实测、判断还是未验证；会变化的事实有一手 URL 与读取日期。
- [ ] 安装与源码记录对应实际环境，不照抄早期“LangChain 未安装”的历史状态。
- [ ] 离线运行 `create_agent_langchain.py`，确认真正使用 SDK 自带假模型与 `create_agent`；没有真实客户端、`.env`、外部追踪或网络请求。
- [ ] 保存两条路径实际工具 ID、顺序、参数、观察、成功状态、模型轮数、结束原因与最终回答；逐项解释 `equivalent`。
- [ ] 保存现场统计的代码行数，分列原生运行时、两边适配、假模型适配与共享代码；解释功能覆盖差异和 SDK 隐藏复杂度，不以“更短”为唯一理由。
- [ ] 在隔离副本注入跨租户订单或过低 recursion_limit，记录预期、命令、退出码、实际轨迹及恢复；不能只展示正常路径。
- [ ] 招聘比例只有可复核岗位样本才填写；不把 Stack Overflow 多选使用率冒充市场份额或岗位比例。
- [ ] 结论包含至少一个替代方案和被拒绝的理由，列出迁移消息、状态、工具、审批与评测契约的成本。

## 通过标准

1. 四类方案完整，维度与需求对应，不是堆功能名；每个候选有选择与拒绝条件、退出成本。
2. 离线证据能定位真实框架调度和前章原生循环，轨迹来自实际工具结果；固定脚本的结论不外推为模型质量或性能。
3. 至少一次失败实验有预期与实际差异分析，不修改共享工具或验收标准来掩盖问题。
4. 数据口径和未验证边界明确，不把流行度、文件存在或文档声明当唯一证据。
