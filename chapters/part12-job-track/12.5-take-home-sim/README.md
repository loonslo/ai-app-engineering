# J5 限时 take-home 模拟 · 就业章（任务书 + 离线检查器）

[全书目录](../../README.md) · [上一章 J4](../12.4-llm-system-design-mock/README.md) · [篇首](../README.md) · [下一章 J6](../12.6-behavioral-stories/README.md)

- **目标**：在限定时间内完成 3 份类似真实 take-home 的任务，交付可运行的代码、对坏输出的处理、测试、评测脚本和写明取舍的 README。
- **v3 路径**：J5 / 就业（演练测试）
- **岗位任务 / 面试题型**：T1–T4 / F4、F5
- **节奏**：12 小时，第 5–6 周、第 7–8 周、第 13–14 周各做一份。
- **前置**：L1.10、L2.12、L4.5（做对应任务前需要的基础）。

## 为什么

take-home 是展示“没有人在旁边指点时你怎么交付”的机会。公开资料能提供的信息有限，而且来自面试辅导机构，下面只写我们读到的内容，并标明性质。

## 关于 take-home 的公开说法（读取于 2026-10-31）

来源是面试辅导机构 PracHub 的《Software Engineer Take-Home Assignment Guide 2026》（[链接](https://prachub.com/resources/software-engineer-take-home-assignment-guide-2026-scope-tests-and-submission)，2026-08 发布、10 月更新），属于**辅导机构的整理**，不是统计研究：

- 它说 2026 年的 take-home 形式从“限时的浏览器项目加隐藏测试”到“仓库、PR、已部署应用或上传的压缩包”都有，时长以任务书为准——**我们没有找到权威的“常见时长”统计**，所以不在这里给数字；
- 它列出评审看五类信号：需求、正确性、工程判断、验证、沟通；强调完成必须项后再做质量与附加项（三层范围：必须项 / 质量 / 附加），README 要写“做了什么、怎么运行、怎么测试、决定与取舍、已知限制”；
- 它强调**遵守雇主的 AI 政策**：不明确就问，允许时要能解释并修改每一行。

本课程的做法（课程设计，不是引用）：每份任务书都有限时、固定输入、接口约定、离线检查器和评分表；我们认为“一个能打印分数的小评测脚本”往往让交付更有说服力，所以每份任务都要求你写一个——这是我们的判断，没有统计依据。

## 3 份任务

| 任务 | 限时 | 做什么 | 检查器 |
|---|---|---|---|
| [A 带引用与拒答的文档问答](briefs/a-doc-qa.md) | 4h | 检索 + 引用 + 范围外拒答（不调用模型）+ 失败处理 | `checkers/check_a.py`（6 项） |
| [B 结构化抽取分类器](briefs/b-extraction.md) | 3h | 解析、校验、带原因重试、评测脚本 | `checkers/check_b.py`（6 项） |
| [C 带安全约束的工具调用 Agent](briefs/c-tool-agent.md) | 4h | 有界循环、危险工具审批、工具异常反馈 | `checkers/check_c.py`（7 项） |

每份任务书包含：需求、提供的数据（`fixtures/`，小而可再分发）、接口约定、交付物、评分表。

## 怎么做一次

1. 计时开始前读任务书，**不要看参考实现**（课程仓库里没有公开参考实现）；
2. 把 `starters/` 里的空实现复制到你自己的目录，开始计时；
3. 做完必须项再做质量项；**离限时结束前 30 分钟停止加功能**，从干净环境跑一遍、补 README；
4. 用离线检查器验证：

```bash
python chapters/part12-job-track/12.5-take-home-sim/checkers/check_a.py --module path/to/solution_a.py
```

   检查器用假模型运行固定用例，结构与 gate 相同（`--module` 指定你的文件）；`starters/` 里的空实现应当全部失败；
5. 按[自评表](templates/self-review.md)写：用时、未完成项、评分表自评；
6. 登记到证据索引。

## 常见失败

- 超时仍在加功能，没有留时间写 README 和从头跑一遍；
- 只让检查器通过，没有写自己的测试和评测脚本；
- 范围外问题仍然调用模型（拒答不是“让模型说不知道”）；
- 自评写“全部完成”，其实有未完成项。

## 边界

- 离线检查器只验证接口与固定用例下的行为；它**不评价提示词质量、检索效果或代码风格**，也不能替代真实评审。
- 任务书是练习，不是任何公司的真题。
- 三份任务都用假模型运行；真实模型下的表现需要你自己另行评测并如实记录。
