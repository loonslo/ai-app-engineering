# J2 公开作品节奏 · 就业章

[全书目录](../../README.md) · [上一章 J1](../12.1-positioning-resume/README.md) · [篇首](../README.md) · [下一章 J3](../12.3-coding-interview/README.md)

- **目标**：每周一条公开更新，持续积累可查阅的作品；第 8 周与第 14 周各写一篇较完整的评测方法文章。
- **v3 路径**：J2 / 就业（清单验收）
- **岗位任务 / 面试题型**：T6 / F6
- **节奏**：4 小时，第 3–16 周，每周约 20 分钟。
- **前置**：已经有可以写的内容（篇 11 的项目进展、各章的评测记录）。

## 为什么

招聘方会搜索你的名字。一个持续、诚实、有数字的公开更新历史，比一份突然出现的“完美作品”更可信。它同时满足 E2 的要求之一：一篇评测方法文章。

## 步骤

1. **每周一条公开更新**（[模板](templates/weekly-update.md)）：问题、做法、评测数字、失败、下一步。每条控制在 300 字以内，**失败也要写**。
2. **发布位置**：GitHub README 或 Pages、个人博客。选一个你能长期维护的。
3. **隐私**：不公开密钥、内部数据、真实用户信息、未公开的公司信息；访谈对象用代号；截图先检查有没有 token 与个人信息。
4. **第 8 周与第 14 周各写一篇较完整的评测方法文章**（[提纲模板](templates/eval-article-outline.md)）：选一个你真实做过的评测问题（golden set 怎么来、指标怎么定、judge 怎么校准、一个失败案例）。文章里所有数字都要有来源。
5. 打卡：用 CHECKLIST 里的 14 周表记录。

## 产物与验收

见 [CHECKLIST](gate/CHECKLIST.md)。验收看：更新是否按周连续；每条是否包含失败或限制；两篇文章是否有可复现的数据与方法。

## 常见失败

- 只在想起来的时候发一大篇，之后断更；
- 只写成功，读者看不出你怎么思考；
- 文章里引用的数字没有来源，或来自离线替身却写成“真实评测”；
- 发布前没检查截图里的密钥、内部链接。

## 边界

- 本章不覆盖如何获得读者与传播；“有人看”不是验收项。
- 公开内容会长期存在，发布前请按所在公司与保密协议的要求自行判断能写什么。
