## 1. 2026 年招聘市场的四个核心事实

进入 2026 年，大模型技术的行业落地正在经历从“炫技 Demo”到“高可靠工程与降本提效”的深刻转变。根据全球主流招聘统计与行业报告，当前市场呈现以下四个关键特征：

> [!NOTE]
> 以下市场统计数据摘自本课程调研报告（见 [curriculum-v3.md](../../../docs/curriculum-v3.md) 第 8 节与附录），原始数据由调研人员于 **2026-10-27** 读取与核对。招聘市场动态变化迅速，若距离读取日期超过 6 个月，请注意相关数值可能过时。市场数据仅作为学习规划与岗位画像的宏观背景，不作为个人能力的最终结论。

1. **入门级初级岗位极少（Entry-level Squeeze）**：
   求职统计（来源：[Rockstar Developer University 入门岗位统计汇总](https://rockstardeveloperuniversity.com/entry-level-software-engineer-job-market-statistics/)、[365 Data Science 2025/2026 报告](https://365datascience.com/career-advice/career-guides/ai-engineer-job-outlook-2025/)，读取日期：2026-10-27）显示，市场上挂牌的初级/初入行 AI 岗位占比仅约 **4.5%–12%**。企业极少招聘“零工程经验、只读过 API”的新人直接承担 AI 开发。
2. **工程经验与云平台要求高（High Engineering Bar）**：
   招聘分析（来源：[Axial Search AI 岗位需求与经验要求](https://axialsearch.com/insights/ai-engineering-job-demand)，读取日期：2026-10-27）显示，约 **67%** 的 AI 工程岗位明确要求 3 年以上传统软件工程或系统开发经验，约 **56%** 的岗位硬性要求云原生环境（AWS/GCP/Azure、Docker、Kubernetes、CI/CD）的部署与交付经验。
3. **评测类岗位与前置交付工程师（FDE）高速增长**：
   随着企业私有化模型和垂直业务的上线，质量保障与现场落地成为刚需（来源：[TechCrunch: Forward-Deployed Engineers 成为行业新热点](https://techcrunch.com/2026/07/30/forward-deployed-engineers-are-the-ai-industrys-latest-talent-obsession/)、[Talex: What is an AI Evaluation Engineer](https://www.talex.co/insights/what-is-a-ai-evaluation-engineer-and-why-companies-are-hiring-for-it-now)，读取日期：2026-10-27）。专门负责评测集构建、LLM-as-a-Judge 调优、回归防护的“AI 评测/质量工程师”，以及深入客户现场对接的“FDE / 交付工程师”需求显著攀升。
4. **评测与质量工程能力是面试中的强信号**：
   行业调研（来源：[Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)、[Datadog: State of AI Engineering](https://www.datadoghq.com/state-of-ai-engineering/)，读取日期：2026-10-27）表明，能够讲清“如何量化模型幻觉、如何构建 Golden Set、如何设计带有人工校准的 Judge 机制、线上事故如何归因与自动化回归”的候选人，在面试中更容易从同质化的候选人中脱颖而出。这正是测试工程师转型的最大差异化护城河。

## 2. 四类目标岗位画像与预期匹配度

基于“测试/质量工程背景 + AI 评测与应用交付”的转型定位，我们将目标岗位与预期匹配度划分为四类（引自 [outline.md 第 1 节](../../../docs/v3/outline.md#1-目标)）：

| 目标岗位 | 预期匹配度 | 主要技术支撑与产物 |
|---|---|---|
| **AI 评测 / AI 质量工程师** | **高** | 贯穿全课程的自动化 Eval Harness、Golden Set 构建、LLM-as-a-Judge、回归门禁与指标报告 |
| **中级 AI 应用工程师** | **中** | 基础模型 API 原语、确定性结构化抽取、企业 RAG 系统、有状态 Agent 与真实上线运行的主作品 |
| **FDE / 交付工程师** | **中低** | 工程化交付、客户系统对接、私有化部署、Docker 容器化；国内方向结合本地模型推理能力 |
| **大厂核心算法/架构师** | **低** | 需要深厚的机器学习算法训练、预训练/大模型微调理论以及极强的底层高并发分布式架构深度 |

> [!NOTE]
> 匹配度是基于当前背景和技能树的客观审查判断，不是统计学必然。通过严谨的证据积累，可以逐步提升对应岗位的胜任力。

## 3. 怎样拆解一份目标 JD

在分析目标岗位的招聘需求时，不要被冗长、罗列的关键词吓倒。应使用结构化方法拆解为岗位任务（T1–T7）与面试题型（F1–F6）：

### 3.1 对照岗位任务（T1–T7）分类
- **T1**：把 LLM 功能嵌入现有系统（如工单分类、文本抽取、确定性输出校验）。
- **T2**：基于企业资料的检索问答（RAG 多路召回、切分、重排、权限过滤、真实引用）。
- **T3**：能执行动作的业务 Agent（带持久化、人工审批 HITL、中断恢复与容错）。
- **T4**：评测与质量改进（评测集 Golden Set 构建、判分一致率校准、回归测试门禁）。
- **T5**：生产运维与可靠性（部署、OpenTelemetry 观测、成本控制、安全合规）。
- **T6**：需求与沟通（业务目标拆解、LLM 输入输出契约设计、与传统服务打通）。
- **T7**：用编码 Agent 高效开发，并具备严谨的人工 diff 审查与防御性验证能力。

### 3.2 区分硬性要求（Must-have）与加分项（Nice-to-have）
- **硬性要求**：直接决定简历初筛能否通过的核心门槛（如语言基础、RAG 或评测项目经历、云端部署能力）。
- **加分项**：有加分但没有不致命（如了解前沿框架、有过学术论文发表、熟悉微调等）。

## 4. 按证据自评规则（严禁“按感觉打分”）

转型中最常见的自我误判是“我看过相关的博客，我觉得我懂了”。在填报能力时，必须严格执行**按证据打分**的量化标准：

- **0 分（未接触）**：没接触过，不清楚技术细节和底层原理。
- **1 分（有概念）**：看过文档、论文或视频讲解，能讲清概念，但没有独立动手写过代码。
- **2 分（离线练习）**：亲手写过代码，在本地通过了离线单元测试或离线 Gate 检查。
- **3 分（真实运行与上线证据）**：调用过真实大模型 API、系统公网部署运行、积累了真实请求流量、或有详细的真实评测报告与事故复盘记录。

## 5. 怎样将 16 周排期落地到个人日历

根据 [outline.md 第 7 节](../../../docs/v3/outline.md#7-16-周排期) 的节奏，整体路线规划如下：

1. **第 1–2 周**：L0 工程底座通关，完成 L1.1–L1.9 基础模型调用与原语。
2. **第 3–4 周**：L1.10 嵌入式功能独立仓库；开启企业级 RAG 模块（L2.1–L2.8）；启动就业轨道 J1（简历草稿）与 J3（算法演练）。
3. **第 5–6 周**：RAG 评测与进阶，**在第 6 周末前完成主作品 P2 的公网最小上线**！
   > 为什么必须在第 6 周末前最小上线？
   > 因为就业出口标准（E1）要求主作品**在公网持续稳定运行 ≥4 周，且积累真实用户与真实请求**。若拖延到课程后期才上线，将无法积累足够的运行时证据。
4. **第 7–12 周**：专项评测与质量保障（L3）、生产级 Agent（L4）、演示前端开发（P5）、系统设计模拟（J4）。
5. **第 13–16 周**：生产级运维观测（L5）、真实评测与事故复盘（P4）、完善项目叙事（P6）、集中投递与面试复盘（J7）。

**缓冲时间安排**：
每周建议留出 10%–20% 的无安排弹性时间，用于应对技术攻关卡点或生活琐事；在职学习者可按 1.5 倍或 2 倍周期（24–32 周）同比例放缓推进。

请使用本章节提供的 3 份标准模板完成自评与规划：

1. **收集与拆解 JD**：
   在各大招聘网站（如 Boss直聘、拉勾、LinkedIn 等）寻找 3 份符合目标定位的真实 JD，记录来源链接与读取日期，使用 [templates/jd-breakdown.md](templates/jd-breakdown.md) 逐项拆解。
2. **完成差距自评**：
   使用 [templates/self-assessment.md](templates/self-assessment.md) 针对 T1–T7 逐项按证据客观打分，找出最大缺口。
3. **制定 16 周日历**：
   使用 [templates/schedule-16w.md](templates/schedule-16w.md) 将学习计划、项目里程碑和就业准备工作映射到你真实的日历中。
4. **记录证据**：
   在 [workbook.md](workbook.md) 中记录自评总结与证据路径，对照 [gate/CHECKLIST.md](gate/CHECKLIST.md) 完成自检。
