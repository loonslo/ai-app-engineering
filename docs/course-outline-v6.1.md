# AI 应用与 Agent 开发：用一个报销助手讲清常见工程问题

版本：v6.1 · 独立文章与连续项目实践版  
修订日期：2026-11-05  
结构：11 章，66 节；每节对应一篇独立文章。包含新增 11 篇工程文章；另附连续项目实践与作者备忘。

这套文章从一张报销单开始。先用 Python 查出记录，再让模型根据资料回答问题。随着功能增加，逐步讨论检索、数据库、审批、权限和服务运行。

报销业务只是共同的例子。读者可以顺着目录做出一个助手，也可以直接阅读自己需要的主题，例如工具调用、文档切分或任务恢复。文章会说明需要哪些基础，并提供本篇的起始材料。

本文是下一轮文章编写的大纲。文中列出的代码包、数据集、演示与验证结果均为待制作内容，不表示已经交付或通过测试。它也不替换仓库当前的课程目录。

## 阅读与发布方式

“章”用于归类，“节”就是发表单位。节内可以有解释、示例和实验，不再把这些小标题当作独立课次。

每篇文章围绕一个主要问题展开。开头用几句话交代当前程序、输入和现象；正文解释相关机制并做一个可观察的改动；结尾停在实验结果、适用条件或尚未处理的情况。没有必要每篇都安排故障，也不要求全部写成同一种七步模板。

独立阅读不等于没有前置知识。数据库文章可以要求读者理解基本 SQL，前端文章可以要求读者会 JavaScript；需要补课时给出相关篇目。运行本篇则不依赖读者手动拼接前几篇代码。

代码类文章的“起始材料”会作为单独的 starter 包提供，包含本篇所需的完整小程序、合成数据和运行说明。需求、选型等文章则提供可独立使用的案例与记录模板。前文链接用于进一步解释，不代替本篇必要的代码与背景。

## 第 1 章：写出第一个能运行的 AI 程序

本章使用终端、编辑器和 Python。首次配置环境的说明放在 1.1 的附件中，其余文章也保留各自的环境检查入口。

### 1.1 在电脑上运行一张报销单

- **问题与内容**：程序怎样显示单号、金额和状态？从运行一个短脚本开始，修改变量，观察保存、工作目录与报错行号。
- **前置与起始材料**：无需编程经验；提供单文件脚本、Windows/macOS 环境说明和预期输出。
- **结果与范围**：重新打开终端后仍能运行，修改状态后输出变化。只介绍本例用到的字符串、变量和打印，不展开完整 Python 语法。

### 1.2 从 JSON 文件里查出一张报销单

- **问题与内容**：记录增加后，怎样按单号查找？用字典、列表、循环和函数读取 JSON，处理不存在的单号，并写出第一条测试断言。
- **前置与起始材料**：会运行脚本；提供三张合成单据、函数骨架和可运行测试示例。
- **结果与范围**：新增记录、打乱顺序后仍能查对，查不到时返回明确空值。只做本地读取，不加入数据库和模型。

### 1.3 发出一个问题，读回模型的回答

- **问题与内容**：Python 程序怎样与模型通信？配置环境变量，发送一条问题，找到响应中的正文、结束状态与用量信息，并观察缺少配置和超时的结果。
- **前置与起始材料**：理解函数和字典；提供调用模板、变量名示例和脱敏响应样本。
- **结果与范围**：有服务访问条件时完成一次真实调用；否则先阅读明确标注的响应样本。字段按本篇选定的接口讲解，不混用不同接口结构，不展开自动重试。

### 1.4 把一次模型响应保存下来，供本地调试使用

- **问题与内容**：同一个问题每次回答不同，测试怎样重复运行？保存请求特征与脱敏响应，以匹配请求的方式回放，区分录制数据与人工测试替身。
- **前置与起始材料**：理解请求和响应；提供完整小客户端、已录制样本和模拟异常。
- **结果与范围**：相同测试输入得到固定结果，未录制输入明确报错。回放用于验证程序分支，不能证明真实模型回答质量，也不默认把未匹配请求转成付费调用。

## 第 2 章：让助手查资料、调用工具

本章先使用少量 JSON 资料。这样可以直接看见程序查到了什么，再观察模型怎样使用这些结果。

### 2.1 先查制度，再让模型回答

- **问题与内容**：模型不知道公司的报销制度时，程序可以提供哪些依据？按条款号或限定关键词找出原文，再拼成回答上下文。
- **前置与起始材料**：会调用模型、读取 JSON；提供四条制度、查询函数和回答模板。
- **结果与范围**：回答带可定位的条款标识，原文由程序读取；无匹配时明确说明缺少依据。从本篇开始按 10.1 保存正常、无答案和错误引用样本。修改制度后重新运行比较结果，不预设模型一定会编造答案。向量检索留到第 5 章。

### 2.2 模型提出工具调用后，Python 怎样执行

- **问题与内容**：模型返回工具名和参数后会发生什么？依次查看工具说明、参数校验、本地函数执行、结果回填和最终回答。
- **前置与起始材料**：理解函数调用与模型消息；提供一个查单工具、两次模型响应及完整调度骨架。
- **结果与范围**：能对应每一步的输入与输出；未知工具和非法参数被程序拒绝。保留正常与失败轨迹，作为后续工具回归的起点。只处理一个只读工具，不加入多工具规划。

### 2.3 查完单据，再根据需要查制度

- **问题与内容**：一个问题需要两份资料时，助手怎样继续查？注册查单据和查制度两个工具，分别观察一步查询、两步查询和资料不全的情况。
- **前置与起始材料**：理解工具结果回填；提供双工具程序、单据与制度数据、三组回放。
- **结果与范围**：保留本轮实际取回的证据；只找到退回备注时不补写不存在的制度。缺参追问与会话保存单独在 2.4 讨论。

### 2.4 用户补充一个单号后，怎样接着上一轮回答

- **问题与内容**：用户先问“为什么退回”，随后补充单号，程序怎样关联两轮输入？保存消息历史，明确会话标识、缺参追问和清空会话的行为。
- **前置与起始材料**：理解模型消息与工具；提供两个测试会话和已接好的双工具助手。
- **结果与范围**：补充单号后继续查询，不同会话互不混用。演示超长历史的明确截断或提示策略，不把整个历史无限追加，也不实现长期记忆。

### 2.5 给工具调用循环设置结束条件

- **问题与内容**：助手一直查询或等待接口时，程序怎样结束？设置总步数、请求超时和重复无进展检测，给每种终止原因单独记录状态。
- **前置与起始材料**：会读循环与异常处理；提供正常、重复调用和超时三组响应序列。
- **结果与范围**：成功、超限与超时均有明确出口。相同参数不自动等于错误；示例结合结果是否变化判断无进展，不把这里的阈值当成所有业务的通用配置。

### 2.6 回答错了，先沿着运行记录看一遍

- **问题与内容**：引用错条款时，怎样分清查错记录、传错参数和生成错误？把一次执行记录成请求、工具调用、返回证据与结束原因。
- **前置与起始材料**：理解双工具执行；提供三份脱敏失败记录和最小日志器。
- **结果与范围**：为每个例子指出第一次偏离预期的位置，并验证一处针对性修复。只做本地排查，不要求先搭追踪平台；样本统计在第 10 章展开。

## 第 3 章：把模型接进一个具体功能

本章把已能调用的函数放进网页和业务流程。每篇都带自己的调用替身，页面和数据校验可以先在本地调试。

### 3.1 给查询助手加一个本地网页

- **问题与内容**：怎样让别人不用终端也能提问？用 FastAPI 和原生 HTML/JavaScript 接入一个现成的问答函数，展示回答、原文、等待和错误状态。
- **前置与起始材料**：会调用 Python 函数；提供可运行网页模板和固定响应替身，并解释本例涉及的 HTTP 请求。
- **结果与范围**：正常、空输入和服务错误均有页面反馈。本篇只在本机运行，不加入登录、React 和流式传输。

### 3.2 从票据文本里抽取固定字段

- **问题与内容**：怎样把一段票据文本整理成程序可处理的数据？定义字段、类型和缺失表示，使用所选模型支持的结构化输出方式，并在本地解析校验。
- **前置与起始材料**：理解字典与模型调用；提供合成 OCR 文本、字段定义和包含拒绝或不完整响应的样本。
- **结果与范围**：返回候选单据或明确失败状态。结构符合要求并不表示内容真实；金额关系在 3.3 校验，OCR 本身不在本篇实现。

### 3.3 字段都齐了，金额为什么还是对不上

- **问题与内容**：明细、总额、币种之间怎样校验？使用 Decimal 处理金额，写出字段间的业务规则，把原始票据矛盾与可修正的格式错误分别处理。
- **前置与起始材料**：理解结构化记录；提供候选单据、Pydantic 校验骨架和合成异常样本。
- **结果与范围**：合计不符、负金额和币种不一致进入明确错误或人工复核分支，不让模型改数字凑总额。只验证给定规则，不证明票据真实性。

### 3.4 报销初审步骤固定时，直接写一个 Workflow

- **问题与内容**：已知要检查格式、分类和资料完整性时，怎样组织流程？用普通函数描述串行步骤、条件分支和中止原因，再与工具循环处理同一任务作比较。
- **前置与起始材料**：会写函数和条件判断；提供相同输入集、检查函数与 Agent 对照程序。
- **结果与范围**：列出路径、调用次数和错误样例；真实耗时与费用另行实测。对照结果不预填，不把固定流程强行改造成动态 Agent。

### 3.5 批量检查时，怎样限制同时发出的请求

- **问题与内容**：多个外部检查可以并行时，怎样避免阻塞或发出过多请求？比较串行与异步调用，加入并发上限、超时和单项失败结果。
- **前置与起始材料**：理解函数与异常；提供模拟延迟接口、批量输入和逐步解释的异步骨架。
- **结果与范围**：观察实际最大并发数及失败项，其他任务按既定策略完成或取消。模拟延迟只说明调度行为，不作为真实模型加速数据；网页停止操作在 9.2 讨论。

### 3.6 “做一个报销助手”，怎样写成可以验收的需求

- **问题与内容**：一句功能描述往往没有说清谁使用、依据什么资料、答错会怎样。围绕“员工查询退回原因”整理输入、允许动作、资料范围、无法回答时的去向，与当前人工处理方式作比较。
- **前置与起始材料**：无需先做完前文；提供一段合成需求访谈、现有查询流程、含歧义的问题和一页需求记录模板。
- **结果与范围**：形成可讨论的功能边界、成功/失败例子、质量与运行目标、暂不处理事项及待确认问题。把业务方原话、作者假设和已经确认的决定分开；未知指标留待确认，不预填一个通用准确率。需求记录用于后续实验，不承诺任何业务都适合引入模型。

### 3.7 同一组业务问题，怎样选择合适的模型

- **问题与内容**：怎样知道一个模型是否适合当前任务？先建立直接查询或规则方案的基线，再比较两个可用模型的任务完成情况、格式兼容、耗时与单次成功任务的估算成本。
- **前置与起始材料**：会发起模型调用；提供明确任务、开发/保留样本划分、固定上下文、统一业务提示词与记录程序。无需先搭评测平台。
- **结果与范围**：先核对数据处理条件、服务区域与所需能力，再在同一输入上比较；协议适配差异单独记录。包含失败、重试与放弃任务的成本，保留重复运行的波动和不确定样本。没有真实调用条件时，只完成比较设计和回放演练；本篇选模型，10.6 再固定模型改提示词，不同时改变多个因素后归因。

## 第 4 章：保存数据，识别用户，限制操作

数据库起点采用 PostgreSQL，以便后面的事务和检索文章共用数据格式。每篇提供本地启动配置、建表与种子数据，不要求读者先搭完全部服务。

### 4.1 把 JSON 报销单存进数据库

- **问题与内容**：记录怎样在程序重启后继续查询？介绍本例需要的表、主键、字段、连接和查询，把合成 JSON 导入 PostgreSQL。
- **前置与起始材料**：理解字典和查询函数；提供数据库启动配置、初始化脚本与 SQLAlchemy 查询骨架。
- **结果与范围**：导入后按单号查找，重新启动仍能读到记录。解释初始化与后续结构迁移的区别，不同时展开复杂 ORM 设计。

### 4.2 保存单据成功，写审计记录失败，怎样一起回滚

- **问题与内容**：一次业务操作写入多张表时，哪些操作应共同成功？在事务中保存单据和审计记录，观察中间步骤失败后的数据。
- **前置与起始材料**：理解基本插入与查询；提供已建表的小服务和可触发失败的审计写入函数。
- **结果与范围**：成功时两份记录都在，失败时均不提交。事务范围限于本地数据库，不把外部模型或付款请求当作可一并回滚的数据库操作。

### 4.3 两个人同时提交报销，预算怎样扣才不会超额

- **问题与内容**：先查余额再扣减会怎样竞争？用两个并发请求复现，再比较条件更新与行锁两种实现。
- **前置与起始材料**：理解事务；提供预算表、同步起跑的并发测试与固定金额样例。
- **结果与范围**：按初始预算和申请金额计算预期成功数，核对余额、单据与审计记录。使用真实本地数据库验证竞争，不用内存替身证明数据库锁有效。

### 4.4 登录之后，后端怎样知道当前用户是谁

- **问题与内容**：请求里携带的信息怎样成为可信身份？借助已配置的本地 OIDC 身份服务和登录模板，查看登录结果、会话建立及后端身份上下文。
- **前置与起始材料**：理解请求与响应；提供本地测试账号、登录模板和无效凭据样本。
- **结果与范围**：有效登录形成服务端身份，伪造和过期凭据被拒绝。区别登录身份与 API 访问凭据；本篇不自建身份提供方，也不把登录成功等同于拥有审批权限。

### 4.5 同样登录成功，为什么不能查看别人的报销单

- **问题与内容**：用户身份确定后，怎样判断能否访问某条记录？围绕租户、记录归属与审批职责实施资源授权，将检查放在服务端业务入口。
- **前置与起始材料**：理解身份上下文；提供已接登录的服务、两租户数据和员工/主管测试身份。
- **结果与范围**：查询与修改均覆盖跨租户、同租户不同归属、额度不足等场景。离线身份替身与真实登录验证分别报告；数据库 RLS 可作为扩展实验，不与本篇同时起步。

### 4.6 接入已有报销接口，先处理返回值和失败约定

- **问题与内容**：本地查询函数换成已有系统的 HTTP 接口后，怎样隔开外部格式变化？定义小范围适配层，映射业务标识、分页结果、错误类型和请求关联标识，处理超时、限流与身份失效。
- **前置与起始材料**：理解 HTTP 与资源授权；提供接口说明、独立运行的合成上游服务、客户端骨架和契约测试。上游数据、账号和密钥均为练习用途。
- **结果与范围**：外部增加字段不会随意改变内部返回格式，必要字段缺失或权限失效时有明确失败；读请求的有界重试与写请求的重复执行风险分别说明。先接一个只读端点，不把 ERP、OA、工单平台各自展开；运行本地上游属于集成模拟，接真实系统另留验证记录。

### 4.7 外部资料不断变化，增量同步怎样续跑

- **问题与内容**：接口分页拉到一半失败后，怎样继续，并识别更新、删除和权限变化？记录来源标识、版本与同步游标，让一批变更写入成功后再推进游标，重复批次按稳定标识处理。
- **前置与起始材料**：理解外部接口和数据库事务；提供带分页、变更序号及删除标记的合成资料服务，可重放重复与乱序批次。
- **结果与范围**：中断续跑不漏页，重复数据不重复入库，旧版本不会覆盖新版本，删除或撤权影响检索与缓存。游标、更新时间和删除通知取决于上游约定；本篇明确选择变更序列方案，无删除通知的上游需另做全量核对。索引更新尚未完成的资料不被误报为已同步可用。

### 4.8 数据库增加一个字段后，旧版本服务还能不能运行

- **问题与内容**：给单据增加截止日期，怎样同时照顾旧记录和新旧应用？用版本化迁移先增加兼容字段，再回填与切换读取方式，最后讨论什么时候可以收紧约束或移除旧字段。
- **前置与起始材料**：理解事务和建表；提供旧版服务、带历史数据的数据库、Alembic 迁移骨架及新版需求。
- **结果与范围**：验证旧记录、回填中断、重复执行和新旧应用并存；记录迁移耗时与锁等待。应用回退不自动恢复数据库旧结构，回退窗口内保留必要兼容。练习只针对一项结构变化，备份恢复在 11.9 演示，不把删库重建当作迁移。

## 第 5 章：让问答助手查到合适的资料

每篇保留文档来源和片段标识。解析、切分、召回、重排、上下文与生成分别观察；检索改善与回答改善分别记录。

### 5.1 PDF 提取出的文字，为什么会丢失表格含义

- **问题与内容**：原文看得懂，提取结果为什么读不通？检查文本顺序、页码、表头与跨页表格，输出保留来源的规范化内容。
- **前置与起始材料**：会读取文件；提供自制 PDF、可运行提取脚本和人工核对文本。
- **结果与范围**：逐项比较提取内容与原页，标记无法可靠解析的部分。主例只处理文本型 PDF；扫描件 OCR 作为额外条件说明，不承诺一种方案处理所有版式。

### 5.2 文档应该在哪里切开：按长度切分与按标题切分

- **问题与内容**：一条制度被切成两半后还剩多少含义？比较两种切分方式，保留标题、条款号、表头和必要的重叠内容。
- **前置与起始材料**：会处理字符串；提供规范化 Markdown、两种切分器和固定查询样本。
- **结果与范围**：检查片段是否可读，并比较关键依据是否完整落在候选片段中。给出片段 ID 与来源映射，不在本篇调优重排模型。

### 5.3 关键词不同，怎样找到意思相近的条款

- **问题与内容**：问题写“打车”，条款写“市内交通”，怎样比较语义？对准备好的片段做向量化，写入 pgvector，再查看相似度排序。
- **前置与起始材料**：理解数据库查询；提供预切分资料、数据库配置、固定向量样本及真实嵌入调用入口。
- **结果与范围**：分别运行语义相近与无关问题，观察候选结果。固定向量只用于程序测试；真实召回效果需要实际嵌入模型。相似度高不直接代表足以回答。

### 5.4 条款编号与自然语言问题，怎样一起检索

- **问题与内容**：编号查询与语义查询需要不同信号时，怎样合并结果？先分别查看编号/关键词与向量候选，再用 RRF 融合排名。
- **前置与起始材料**：理解候选列表；提供两路检索器、中文分词配置和包含精确编号的查询集。
- **结果与范围**：比较各路与融合后的命中情况，保留失败样例。编号可独立精确匹配；中文分词需单独检查，不把默认全文检索当作现成中文方案，也不把 RRF 称为语义重排模型。

### 5.5 找到了相关片段，为什么仍然没有排到前面

- **问题与内容**：正确片段已经在候选集中，怎样改善排序？接入一个重排器，比较重排前后的位置与耗时。
- **前置与起始材料**：理解召回与排序的区别；提供冻结的候选列表、相关性标注和重排调用入口。
- **结果与范围**：报告排序改善、退化和耗时；单列候选中根本没有答案的情况。回放可验证排序代码，真实重排质量另测；本篇不扩大召回范围掩盖排序问题。

### 5.6 检索结果怎样交给模型：去重、长度限制与引用

- **问题与内容**：取回的资料怎样组成可用上下文？处理重复片段、低相关结果和长度预算，把可引用的来源映射交给回答程序。
- **前置与起始材料**：理解检索结果与模型调用；提供重复、过长、无关及空结果四类输入。
- **结果与范围**：上下文长度有界，引用能定位原文，资料不足时明确说明。引用存在与回答受到原文支持分别检查；本篇不通过添加无关片段来凑足候选数。

### 5.7 制度更新后，怎样避免继续引用旧版本

- **问题与内容**：同一份制度换了内容，索引怎样跟着更新？记录文档版本、内容摘要与有效状态，完成增量导入和旧版本失效。
- **前置与起始材料**：理解检索表与事务；提供两版合成制度、已有索引和更新脚本。
- **结果与范围**：重复导入不产生重复片段，新查询只使用当前有效版本，旧引用按明确规则提示失效或查看获准历史版本。用户撤权与答案缓存放在 7.2。

## 第 6 章：保存任务进度，等待人工审批

本章用合成单据和模拟执行网关。状态图负责记录进度和选择路径，业务函数负责校验与写入；二者在图示和代码中分别呈现。

### 6.1 把工具循环画成一张能执行的状态图

- **问题与内容**：步骤增加后，怎样看清当前状态和下一步？用 LangGraph 表达模型提议、工具执行、错误处理和结束节点。
- **前置与起始材料**：理解有界工具循环；提供原生循环、对应状态字段及固定模型替身。
- **结果与范围**：先写出节点输入输出、边条件、失败分支和终止条件，再比较两种实现的运行轨迹。本篇使用内存状态，不声称能跨进程恢复。

### 6.2 程序重启后，怎样接着处理未完成的任务

- **问题与内容**：进度不能只放在局部变量中时，怎样保存与恢复？加入持久化检查点，通过任务标识找回状态，观察不同故障位置的恢复行为。
- **前置与起始材料**：理解状态图；提供完整小图、数据库配置与可控终止点。
- **结果与范围**：重启后核对状态与节点执行记录，并测试不同任务不混用。检查点保存图状态，不保证外部写操作只执行一次；重复执行由 6.5、6.6 处理。

### 6.3 流程走到审批处，怎样暂停并等待一个决定

- **问题与内容**：主管还没有回应时，程序怎样停下来？使用 interrupt 与恢复输入，分别处理批准、拒绝、过期和无权操作。
- **前置与起始材料**：理解持久化状态和资源授权；提供已接权限的小服务与简单审批图。
- **结果与范围**：暂停后可重启并继续，错误身份不能恢复任务。展示恢复时节点从头执行的行为；本篇恢复后的动作只写模拟结果，不接真实付款。

### 6.4 审批时看到的金额，怎样与执行时保持一致

- **问题与内容**：审批期间汇率或单据被修改怎么办？在等待前保存提案内容与版本，让批准记录绑定该版本，执行前再次核对。
- **前置与起始材料**：理解人工审批；提供可暂停流程、模拟汇率和持久化提案表。
- **结果与范围**：修改金额、版本、有效期或审批者权限后，旧批准不能继续执行。内容摘要用于识别变化，身份授权仍由服务端完成；不把哈希本身当作批准证明。

### 6.5 同一笔申请重复提交，怎样避免重复执行

- **问题与内容**：双击按钮、客户端重试和工作进程重跑会怎样重复写入？为业务操作定义稳定幂等键，记录执行结果并处理并发重复请求。
- **前置与起始材料**：理解事务与审批记录；提供执行表、唯一约束和支持幂等请求的模拟网关。
- **结果与范围**：相同业务请求返回同一执行结果，不因重试生成新的操作身份。结论限于本地约束及网关约定，外部结果未知时不靠本地去重猜测成功与否。

### 6.6 外部接口超时后，怎样确认这笔操作有没有完成

- **问题与内容**：没有收到成功响应，是否可以重发？分别处理已成功、处理中、结果未知、明确未执行和终态失败，增加查询与人工处理入口。
- **前置与起始材料**：理解幂等请求；提供五类远端状态、模拟查询接口和待核对执行记录。
- **结果与范围**：未知状态不会触发新的付款请求；确认成功后补记本地结果，审批失效也不抹去既有成功事实。重试前重新检查授权；无法查询时保持待处理，不假定所有网关都支持同一种对账方式。

### 6.7 状态图升级后，昨天暂停的任务怎样继续

- **问题与内容**：给流程增加字段或调整节点后，旧检查点会被怎样读取？区分字段兼容与业务规则兼容，保留必要的旧节点入口，并在状态中记录业务流程版本。
- **前置与起始材料**：理解持久化状态图；提供旧版图、暂停与失败中的检查点、执行台账及一项新版变更。
- **结果与范围**：恢复旧任务、启动新任务、回退应用各有测试；不支持自动迁移的任务进入可观察的人工处理状态。数据能够加载，不等于可继续使用旧批准执行新动作；权限与批准有效性仍按当前规则检查。具体迁移方式以选定 LangGraph 版本和存储格式实测，不把线程标识当作自动锁定代码版本的功能。

## 第 7 章：处理受限资料与不可信输入

本章分别观察“可以检索什么”“已经生成的内容还能否查看”与“资料里的指令是否被执行”。测试覆盖具体路径，不用一组样例宣称系统能防住所有攻击。

### 7.1 不同员工提同一个问题，怎样只检索各自能看的资料

- **问题与内容**：权限怎样参与候选资料选择？使用服务端身份限定文档范围，在检索请求中携带授权条件，并检查候选集与模型上下文。
- **前置与起始材料**：理解资源授权与向量检索；提供两租户、不同角色的制度及已有检索服务。
- **结果与范围**：未授权资料不进入生成上下文；分别测授权正确性和过滤后的召回数量。SQL 权限条件与近似索引内部扫描顺序不是一回事，不能据此宣称索引只扫描获准向量。

### 7.2 权限撤销后，缓存答案和历史引用怎样处理

- **问题与内容**：用户曾经有权查看，后来调岗，旧内容如何再次访问？在缓存中区分用户与权限版本，查看历史回答和原文时使用当前权限检查。
- **前置与起始材料**：理解授权检索；提供含来源依赖的缓存答案、历史记录和可变权限服务。
- **结果与范围**：测试撤权后命中缓存、打开旧回答及点击引用三条路径。服务端阻止后续返回，不能撤回用户已下载或已看到的副本；文档版本失效与权限失效分开记录。

### 7.3 单据备注里出现“忽略规则”，程序会怎样处理

- **问题与内容**：资料可能包含要求模型改变行为的文字，怎样观察影响并限制动作？把资料视为待分析输入，同时在执行端验证工具权限、参数归属和批准记录。
- **前置与起始材料**：理解工具调用与审批；提供合成恶意备注、只读和受保护的模拟写工具。
- **结果与范围**：即使模型提出越权写操作，执行端也拒绝；记录错误回答是否仍会发生。测试包含同一工具的越权参数，不只检查不存在的工具名。提示词约束作为辅助，不当作授权机制。

## 第 8 章：复用工具，比较不同 Agent 组织方式

这一章按需选读。工具需要跨客户端使用时再读 MCP；单个助手已难以处理任务分类时，再比较路由和多 Agent。工具数量本身不作为拆分门槛。

### 8.1 把一个 Python 查询函数提供给 MCP 客户端

- **问题与内容**：已有查询函数怎样被另一种客户端调用？用本地 stdio 服务暴露一个只读工具，查看发现、参数、返回结果和错误。
- **前置与起始材料**：理解 Python 函数和工具调用；提供查询函数、最小客户端与服务骨架。
- **结果与范围**：客户端能发现并调用工具，非法参数有明确错误。仅做本地进程通信，不在这一篇加入远程授权和多 Agent。

### 8.2 MCP 工具放到远程后，谁可以调用它

- **问题与内容**：工具跨进程和网络复用时，身份与权限怎样传到服务端？使用 HTTP 传输和预配置授权服务，串起发现、获取凭据与受保护调用。
- **前置与起始材料**：理解 MCP 工具及资源授权；提供本地可运行的远程服务、授权配置与测试客户端。
- **结果与范围**：测试错误受众、凭据过期、缺少权限和跨租户参数。scope 命名与租户映射属于本例设计；协议版本明确锁定，不假定所有访问令牌都是 JWT。

### 8.3 工具变多以后，先试着缩小每次可选的范围

- **问题与内容**：助手总在相近工具间选错，怎样判断路由是否有用？用同一任务集比较全量工具、明确规则路由和结构化分类后加载工具子集。
- **前置与起始材料**：理解工具清单；提供财务、行政和 IT 合成任务与工具替身。
- **结果与范围**：记录误选、拒绝分类、模型调用次数及真实运行成本。保留分类错误造成的损失，不预设路由一定更好，不在这篇加入多个自治 Agent。

### 8.4 把任务交给另一个 Agent，实际增加了什么

- **问题与内容**：子 Agent 与路由后的单 Agent 有何差别？实现一个有限交接例子，明确交接字段、证据、权限、错误返回与总调用预算。
- **前置与起始材料**：理解路由和会话状态；提供单 Agent 基线、两个子任务及同一评测集。
- **结果与范围**：比较成功与失败样例、耗时和用量，检查敏感上下文是否被多传。只选一种协作方式，不同时讲完所有多 Agent 模式；没有测得收益时保留简单实现。

## 第 9 章：显示执行过程，继续未完成的任务

本章区分对话请求与后台任务。关闭页面是否应停止任务，由功能决定；两种生命周期在各自文章里写清楚。

### 9.1 回答还没生成完，网页怎样先显示已经收到的部分

- **问题与内容**：怎样把模型的分段结果逐步送到浏览器？用 SSE 格式组织文本、结束和错误事件，区分一条网络数据块与一条完整事件。
- **前置与起始材料**：理解 Web 请求；提供模拟生成流、后端入口和原生 JavaScript 页面。
- **结果与范围**：分片或合并传输时仍能正确显示文本并结束。明确使用的浏览器接收方式；本篇不加入后台队列和断线重放。

### 9.2 点击“停止”以后，后端怎样结束本次生成

- **问题与内容**：网页停止显示后，服务是否还在工作？让前端取消、服务端任务取消和上游连接关闭沿调用链传播，并观察资源释放。
- **前置与起始材料**：理解异步任务与流式响应；提供完整流式小程序和可观察的慢速替身。
- **结果与范围**：核对停止后的任务、连接和结束事件，不只检查按钮状态。实际供应商是否停止计算及怎样计费需要另外验证；后台任务不默认随页面断开取消。

### 9.3 把文本、工具进度和审批请求显示在同一个页面

- **问题与内容**：多种事件同时到来时，页面怎样更新？用 React 和 TypeScript 表达事件类型与界面状态，分别处理文本、工具、引用、审批和错误。
- **前置与起始材料**：具备 JavaScript 与基础 React 知识；提供可运行页面、事件样本和受保护接口替身。
- **结果与范围**：重复事件不重复显示，不符合当前状态的事件可记录和处理；无权查看引用时展示明确提示。先用固定事件流验证页面，不让 UI 按钮决定服务端权限。

### 9.4 任务执行几十秒，怎样让它离开一次 HTTP 请求继续运行

- **问题与内容**：批量初审怎样在提交后继续处理？创建持久化任务，返回任务标识，由工作进程消费，写回进度和终态。
- **前置与起始材料**：理解数据库与幂等；提供一种队列实现、工作进程骨架及模拟检查接口。
- **结果与范围**：页面断开后任务继续，工作进程重启后的重复消费按既定策略处理。锁定一种队列方案，不并排实现多个框架；取消任务使用单独业务操作。

### 9.5 刷新网页后，怎样接着显示任务进度

- **问题与内容**：客户端丢失连接后，怎样知道漏掉了哪些事件？保存事件游标，重连时授权并补发，事件过期时回退到任务状态快照。
- **前置与起始材料**：理解持久化任务、事件流和前端状态；提供完整小服务与可触发断线的页面。
- **结果与范围**：重连不重新提交任务，重复事件可去重，其他用户不能借任务 ID 订阅。原生 EventSource 与 fetch 接收流的游标传递方式分别说明，不假定二者自动重连行为相同。

## 第 10 章：判断一次修改是否有效

每篇都提供自己的输入集，因此可以在对应功能完成后提前阅读。离线测试验证确定性行为，真实模型实验观察回答与决策质量；两类结果分开报告。

### 10.1 把几次错误回答整理成一个可重复使用的样本集

- **问题与内容**：零散问题怎样留下来供下次比较？从运行记录提取输入、资料版本、期望行为和失败位置，区分修复样本与保留评测样本。
- **前置与起始材料**：会读工具与检索记录；提供少量合成成功/失败样本及标注表。
- **结果与范围**：每条样本可追溯，争议样本单列，正常与资料不足场景都保留。先整理具体错误，不设一个无法解释的总分，也不在看过评测结果后随意改标准答案。

### 10.2 检索改得有没有用：看候选结果，也看漏掉的资料

- **问题与内容**：更换切分或检索方式后，怎样比较？用同一相关性标注集计算 Hit@K、Recall@K，并逐条查看退化样本。
- **前置与起始材料**：理解检索候选；提供冻结查询集、相关片段集合及两组检索结果。
- **结果与范围**：写清分母、K 和无答案样本的处理方法。检索指标不代替回答质量；没有完整相关性标注时，不把局部命中统计冒称完整召回率。

### 10.3 最终答案看起来对，工具调用过程也对吗

- **问题与内容**：过程里越权、漏校验或重复写入，怎样被测试发现？针对工具轨迹检查参数归属、必要授权和写操作次数。
- **前置与起始材料**：理解工具记录与业务权限；提供答案相近但路径不同的执行样本。
- **结果与范围**：能拦截结果正确但过程违规的例子。固定业务约束才检查固定顺序；对允许多种正确路径的任务，不强求逐步复制参考轨迹。

### 10.4 请另一个模型评回答，怎样知道它评得是否可靠

- **问题与内容**：模型给出的“通过”能否作为依据？选择一个清楚的问题，例如回答是否受到资料支持，写判定说明，再与人工标注比较。
- **前置与起始材料**：理解评测样本；提供人工标注集、模型判定入口和分歧记录。
- **结果与范围**：先定义正类含义，再查看混淆矩阵、误判和漏判；保留独立校准/评测划分。裁判失败或无法判断单列，不悄悄当作通过，不用模型判分替代权限断言。

### 10.5 改完提示词或代码，哪些检查放进持续集成

- **问题与内容**：怎样在下一次修改时发现退化？将确定性测试、固定响应回归和真实模型评测分开运行，保存配置、版本与结果差异。
- **前置与起始材料**：理解 pytest 和基本评测；提供小项目、离线样本集与 CI 配置示例。
- **结果与范围**：故意引入一个确定性错误时检查失败；真实模型结果按约定样本与统计方式比较。首次安装依赖、下载模型和准备数据库需要单列，不把预备环境下的离线运行写成从零全程断网。

### 10.6 改了一段提示词，怎样知道改善了什么

- **问题与内容**：让回答更短或增加例子后，哪些行为发生变化？固定模型、资料和工具，版本化保存提示词与参数，在开发样本上迭代，再用保留样本检查效果。
- **前置与起始材料**：理解基本样本评测；提供同一小助手的两版提示词、数据划分、失败记录和对照执行器。
- **结果与范围**：比较任务完成、证据支持、错误拒答、工具误调用及成本，给出改善和退化样本。预先约定重复次数、停止条件与判定口径，不把读过并据此调参的样本继续当作独立评测。发布记录能指出使用哪版提示词，退化时可恢复旧配置；模型更新另开实验。

## 第 11 章：观察服务，并把它交给别人运行

这一章关注已运行的程序。文章里的性能、成本和稳定性结论只对应明确写出的样本、配置和环境。

### 11.1 一次回答很慢，时间花在了哪里

- **问题与内容**：检索、重排、等待模型与工具执行各耗时多少？为一次请求建立关联标识和分段耗时，使用 OpenTelemetry 展示父子调用关系。
- **前置与起始材料**：理解问答调用链；提供可调延迟的小服务与控制台追踪输出。
- **结果与范围**：能定位人为加入的延迟，区分首段响应时间与整体完成时间。模拟耗时用于验证记录方式，接入外部追踪平台作为可选附件。

### 11.2 记录问题时，怎样避免把原始票据和凭据一起写进日志

- **问题与内容**：排查所需信息与不宜保存的内容怎样分开？用允许字段清单记录事件，为异常、嵌套参数和外部错误响应补脱敏处理。
- **前置与起始材料**：理解结构化日志；提供合成敏感字符串、样本异常和日志处理器。
- **结果与范围**：在正常与失败输出中搜索测试标记，检查请求标识和错误类型是否仍足够排查。样例通过只证明所测路径，不声称能自动识别所有个人信息。

### 11.3 一次回答用了多少资源，哪些成本可以减少

- **问题与内容**：怎样把调用次数、输入输出用量与成本关联起来？按请求汇总已报告用量，区分缓存命中、工具循环、重试和缺失统计。
- **前置与起始材料**：理解模型响应与运行记录；提供脱敏用量样本、带日期的计价配置和对照输入。
- **结果与范围**：比较一次受控改动前后的用量与回答质量。未知用量标为未知，估算费用注明价格日期；不把供应商提示词缓存与应用答案缓存混为一谈。

### 11.4 主模型暂时不可用时，怎样重试或切换

- **问题与内容**：服务报错后继续等待、重试还是降级？按失败类型安排次数和时间预算，检查备用服务支持的结构化字段与工具能力。
- **前置与起始材料**：理解超时与工具调用；提供两种模型适配器替身和可控失败序列。
- **结果与范围**：重试有上限，能力不匹配时明确失败或转人工；授权检查保持一致。真实供应商兼容性单独验证，业务写操作不随模型重试无条件重做。

### 11.5 把项目交给另一台电脑运行

- **问题与内容**：项目离开自己的开发环境后需要哪些材料？整理依赖锁定、环境变量说明、数据库初始化、离线演示、启动与停止方式。
- **前置与起始材料**：会运行服务；提供独立的小项目快照与待补充的 README，不要求完成全部 66 篇。
- **结果与范围**：在干净目录或另一台机器按说明运行，记录环境、步骤与实际失败点，完成一条问答或审批演示。本篇验证交付可用性，不将本地启动写成生产容量、可用性或真实用户验收。

### 11.6 把本地服务发布到一个测试环境

- **问题与内容**：源码怎样成为另一台机器上可重复启动的服务？选择一种容器运行方案，构建版本固定的制品，区分配置与凭据，接入健康检查、HTTPS 入口和独立数据存储。
- **前置与起始材料**：理解服务启动；提供小应用、Docker 构建骨架、测试环境配置模板和预备环境检查说明。
- **结果与范围**：记录代码、镜像、配置、模型和提示词版本；从应用之外调用受保护接口，检查未就绪与缺配置时的行为。测试环境隔离于个人开发目录，网络和数据库权限有明确范围。本篇只选一个部署目标，不扩展为 Kubernetes 全套课程；本机容器不冒称远端部署。

### 11.7 新版本出现问题，怎样停止发布并退回可用版本

- **问题与内容**：服务能启动但回答质量或错误率退化时，怎样发现并回退？使用已部署的两个兼容版本，设置发布前检查、有限试用范围、观察窗口与停止条件。
- **前置与起始材料**：理解部署与数据库兼容；提供旧制品、带受控缺陷的新制品、版本记录和回退步骤。
- **结果与范围**：演示一次停止扩大发布、切回旧版本并核对业务结果的过程，区分代码、提示词与配置回退。已有写入、队列任务与外部副作用不随镜像回退消失；遇到不兼容数据先停止相关写操作并处理迁移，不靠回退应用掩盖数据问题。小测试环境无需模拟大规模多区域发布。

### 11.8 并发增加以后，怎样确定服务的承受范围

- **问题与内容**：请求增加时，队列、连接池和模型限额哪里先到上限？按事先记录的请求分布逐步加压，观察排队、完成耗时、错误、拒绝与资源占用，加入有界队列和适当限流。
- **前置与起始材料**：理解异步调用和运行指标；提供负载脚本、延迟可控的模型替身、测试环境与结果模板。
- **结果与范围**：分别报告替身下的应用容量与有限预算的真实端到端结果；计入被拒绝和超时请求，写清并发、到达速率、样本量和持续时间。测试前确定费用上限与停止条件，不从短时压测推导长期可用性，也不将单请求更快当作系统吞吐提高。

### 11.9 有了备份文件，怎样确认服务真的能恢复

- **问题与内容**：数据损坏后，从哪一份资料恢复，哪些状态需要重新核对？在隔离数据库恢复备份，检查业务记录、权限版本和任务状态，再验证索引重建与应用读取。
- **前置与起始材料**：理解数据库和服务配置；提供合成数据、备份脚本、隔离恢复配置及预期记录清单。
- **结果与范围**：记录可恢复到哪个时间点、可能丢失哪些写入和实际恢复耗时。重启工作进程前核对队列与外部执行台账；数据库恢复不会撤销外部已完成动作。先演练一种 SQL 备份恢复方式，持续归档与跨区域容灾另作扩展；恢复在独立目标上进行，不覆盖练习源库。

### 模块职责与状态归属

| 部分 | 负责什么 | 保存什么，哪里是依据 |
|---|---|---|
| Web 与身份入口 | 接收请求、建立服务端身份、返回结果 | 会话与请求标识；身份来自已验证会话，权限来自服务端权威记录 |
| 上游适配器与同步器 | 对接既有接口，映射字段，续跑同步 | 来源 ID、来源版本、游标、删除标记、待处理变更 |
| 业务数据与授权 | 查询归属、处理草稿和批准，约束写入 | 业务数据库与权限记录为依据，模型文本不写作权威金额或身份 |
| 检索与回答 | 在获准资料内召回、重排、组装上下文和生成 | 索引与缓存是可重建结果；保留来源、版本及引用依赖 |
| 任务执行 | 记录长任务进度、预算、取消与恢复 | 任务表/检查点保存进度，执行台账记录副作用；队列消息可重复 |
| 评测与运行观察 | 关联样本、发布、耗时、结果和错误 | 版本化样本与脱敏记录；真实调用、替身和回放明确标记 |

项目早期可把这些职责写成少量模块，不要求拆成多个服务。同步游标推进前，业务变更和必要的后续索引任务要已可靠保存；分别记录“已取回”和“已可检索”，避免失败后丢掉更新。客户端取消一次对话与取消后台同步任务使用不同入口。

### P0：把需求和第一批样本放在一起

**起点**：一份简短业务描述、合成报销数据和自编制度。没有真实业务方时明确写“课程假设”，不伪装成已完成访谈。

**本阶段工作**：选择一个常用问题，例如“这张单据为什么退回”；记录现有处理步骤、谁有权看哪些内容、模型可做哪些事、资料不足时交给谁处理。把正常、有歧义、无依据、资料过期与无权访问的问题写成样本。

**完成时观察**：另一位读者能按同一说明判定几个回答是否合格。争议项和未知项仍可保留，但标明在解决前会阻止哪一种功能发布。验收目标先记录，再做比较，不在结果不理想时追改口径。

| 目标项 | 记录方式 | 本阶段如何确定 |
|---|---|---|
| 任务完成 | 单据是否查对、解释是否有依据、是否需要转人工 | 业务案例与逐条判定说明 |
| 误答与拒答 | 无依据却作答，以及有依据却拒答分别统计 | 定义错误代价，安全约束单独检查 |
| 运行目标 | 首次反馈/整体完成时间、并发或到达速率 | 来自预期使用方式；未知时先作为实验假设 |
| 成本 | 每次请求与每个成功任务的费用估算，人工复核成本另列 | 日期明确的价格与使用量，缺项不填零 |
| 数据新鲜度 | 来源变更到可查询的延迟，撤权生效路径 | 与上游能力和业务允许等待时间一起确定 |
| 恢复目标 | 可容忍的数据丢失时间与恢复耗时 | 测试环境练习目标，不声称企业 SLA 已获批准 |

数据集先做到每条可解释，不设所有项目统一的条数。记录样本来源和分层，保留一部分不用于调参；实际数量、正负例和重复运行次数在报告里列出。

**留下的材料**：需求说明、假设清单、样本版本、指标定义和数据使用范围。本阶段不产出虚构的准确率或业务节省数字。

### P1：比较一个简单原型与已有办法

**起点**：沿用 P0 的业务范围与样本。先完成查单据、按资料回答和一个最小网页；只有问题需要动态选择工具时才加入工具循环。

**本阶段工作**：以直接查询或规则返回作基线。选择两个具备访问条件、允许处理这些资料的模型，在相同上下文上跑真实样本；记录提示词版本、响应、失败、用量与耗时。随后固定模型，单独改一次提示词。

**完成时观察**：知道哪些任务不需要模型，哪些样本得到改善，哪些仍会失败。样本量小或波动大时只给观察结果，不推断整体优越。所有原始测试数据使用合成、公开获准或明确授权资料。

**失败与继续方式**：无法访问真实模型时，回放和替身仍可验证程序，但“真实效果比较”保持未验证；格式失败、无依据与外部超时各有明确处理，不用看似成功的固定答案替代错误状态。

**留下的材料**：可运行原型、基线与候选对照表、失败样本、模型选择记录和一次提示词修改前后差异。单纯的截图不替代输入与版本记录。

### P2：接入一个会变化的数据来源

**起点**：保留 P1 程序与样本，在旁边运行一个独立合成资料服务；有授权的企业接口时可以替换它，但分别记结果。

**本阶段工作**：接入分页查询，实施增量同步；增加两租户测试身份和资源授权，导入制度并建立检索。先从简单召回做起，出现可复现问题后再比较混合检索或重排。

**完成时观察**：在同一套数据上执行以下变化：新增一条记录、修改制度、删除资料、撤销一个用户的权限、同步中途失败再恢复。核对业务表、索引、缓存与历史引用的结果，并测同步延迟。

**失败与继续方式**：上游拒绝或权限状态无法确认时，不按过期权限继续返回敏感内容。资料删除、上游暂时不可用和完整分页结束是不同状态，不能把一次超时或缺页解释为批量删除。没有删除通知时记录补充核对方案；未具备可靠撤权途径时不宣称实现即时撤权。

**留下的材料**：接口契约、字段映射、重试约定、同步记录、权限测试、检索前后比较与未解决的上游限制。

### P3：发布到测试环境，并演练停止和恢复

**起点**：沿用 P2 的项目，选择一个与开发环境隔离的测试部署目标。可以是自有测试机器或获准云环境；本设计不自动创建资源、付费调用或向外网开放服务。

**本阶段工作**：构建固定制品，配置健康检查、最小网络访问、日志和告警。先用模拟模型做可控负载实验，再在明确费用上限内运行小规模真实调用。发布一个受控缺陷版本，观察、停止并回退；在独立数据库完成一次备份恢复。

**完成时观察**：从应用外部成功访问；某项依赖未就绪时入口不会假报健康；超出承受范围时有明确拒绝或排队策略；受控故障能触发可处理的告警，并找到对应请求。回退后不仅看页面，还核对数据库与执行台账。

**失败与继续方式**：超出费用、延迟、错误或资源阈值就停止本次实验，保存结果而非继续加压。恢复先检查数据与授权，再开放入口和工作进程。备份恢复演练不用真实业务库，镜像回退也不自动回滚数据库写入。

**留下的材料**：部署说明、发布清单、负载条件与结果、告警样例、回退记录、恢复时间与数据核对报告。日志中的凭据与原始个人资料不进入共享成果。

### P4：带着历史数据完成一次需求变更

**起点**：保留 P3 的旧制品、旧数据库、历史回答与样本。有任务功能时，还保留一个未完成任务；没有 LangGraph 的项目无需为此临时引入它。

**变更题**：退回单据新增“补件截止日期”，旧数据没有此字段；日期变化后，查询与展示需要更新。任务分支另外要求旧任务恢复后仍能正确读取原有状态，新任务记录新版字段。

**本阶段工作**：先写变更影响说明，找出现有接口、数据库、页面、缓存和评测中受影响的位置。提交一组可审查的小改动，完成兼容迁移、回填和回归；依照 11.7 做一次可回退发布。有持久化状态图时使用 6.7 验证旧检查点。

**完成时观察**：旧记录可读、旧客户端按约定继续工作，新记录能展示日期；回填中断能继续。已批准动作的金额或含义不因新增字段被重算，权限更新仍按当前权威记录执行。

**协作练习**：由未参与实现的人阅读改动说明，提出一个可复现问题或一项接口疑问；作者回应并补充验证。有条件时通过 PR 完成，没有协作者时标注为自审，不把生成的评审意见当作真人审核。

**留下的材料**：需求变更单、影响范围、迁移记录、新旧兼容结果、评审意见及处理、发布版本和新增失败样本。参考实现完成后不清空旧数据重做一遍来替代兼容验证。

### P5：让别人使用，再完成一次实际反馈修复

**起点**：将当前服务、使用说明和允许测试的数据交给至少一位未参与实现的人。若暂时找不到试用者，先完成交接材料，使用反馈保持待验证。

**本阶段工作**：让对方按自己的表述提问，记录不能完成的任务、误解与等待情况。选择一条反馈，补成可复现样本，定位原因，完成修复并重跑旧样本；向对方解释剩余限制。

**完成时观察**：使用者能完成约定任务，维护者能凭说明找到版本、日志和恢复入口；新增反馈的处理有输入、修改与结果，不只记录“体验更好了”。真实试用者不一定是企业用户，报告中保留这一边界。

**留下的材料**：脱敏反馈、复现与回归、已知问题、运行手册，以及一段可核对的项目说明：自己实现了什么、借助了什么、哪些结果在何种环境测得。

### W：需要写操作时，增加草稿提交与主管确认

**起点**：完成 P2 的身份和数据接入后即可进入，随后与 P3—P5 同步演练。只使用模拟业务系统，不连接付款网关。

**任务状态**：候选草稿生成后进入校验；合法草稿保存为待确认版本。批准、拒绝、过期分别有出口；执行时再次核对批准版本和当前授权。执行结果未知时进入待核对状态，不重新生成操作身份盲目提交。

**节点分工**：抽取节点只产生候选字段；校验与提案节点计算确定值并保存版本；等待节点只等待外部决定；执行节点核对授权并调用幂等业务入口；核对节点处理未知结果。每次恢复记录任务、版本、节点与停止原因。

**完成时观察**：重复点击、进程重启、等待期间修改草稿、撤权、批准过期与上游超时各有确定行为。拒绝和过期终止当前提案；未知结果保留待处理记录，重试次数与等待预算有上限，到限转人工。

**可选扩展**：6.6 的模拟付款对账、外币换算、MCP 工具接入与多 Agent 对照。只有出现对应需求时加入，不以组件数量评判项目完成度。

### 每次实验用同一份记录格式

| 字段 | 填写内容 |
|---|---|
| 要验证的问题 | 具体输入、现象和预期，不写“整体提升” |
| 代码与配置 | 提交或版本标签、提示词、模型标识、依赖与部署版本 |
| 数据与权限 | 样本集版本、来源范围、索引版本、测试身份与授权条件 |
| 环境与方式 | 本地/远端；替身/回放/真实 API；真实或合成业务数据 |
| 实验条件 | 样本量、重复次数、负载、时长、费用上限和停止条件 |
| 实际结果 | 原始样本引用、失败数量与类型、耗时、用量和缺失统计 |
| 结论与限制 | 哪个假设成立、哪些未验证、下一次改变什么 |

状态按阶段记录为“待实施、实施中、待外部条件、已按所列范围验证”。缺少真实模型、测试环境或试用者时保留未验证项，不因教程代码能运行而把整阶段记为完成。

## 附录 B：给作者的简短备忘

### 一篇文章的准备材料

每篇开始写之前，先确定标题、读者需要的基础、本篇输入、起始代码和可观察结果。上述逐节条目是写作任务书；正式文章发布时，可以把这些内容自然放进开头与运行说明，不必原样贴出三项清单。

起始包与参考实现分别保存。故障版本只在确实能帮助解释时提供；不为每篇强行建立四个分支。包内列出依赖版本、运行命令、数据来源、样例输出和测试入口。共用函数可以来自仓库，但单独下载的包中也包含所需内容。

涉及模型时，区分三种结果：真实调用、录制回放、人工测试替身。回放按请求匹配，数据经过脱敏。可以先运行离线样例；调用真实服务所需的环境与费用条件在入口处说明。

### 文字怎样写得自然

开头从一个具体情形写起。例如：

> 报销单保存成功后，程序还要写一条审计记录。如果第二次写入失败，数据库里会留下什么？这一篇用两张表和一个主动抛出的异常，看看事务提交前后发生了什么。

这样的开头已经交代了对象、问题和接下来的操作。不需要先批评初学者的习惯，也不需要说明读者“只有理解这个才算真正入门”。

标题可以混合使用问题与陈述，不必 66 篇都写成“为什么”。正文少用“必须牢记”“正确姿势”“核心铁律”等命令式措辞。涉及安全或数据一致性时，把约束和后果直接写出来，例如“这次批准只对应版本 3，版本变化后需要重新确认”。

代码的关键位置写简短中文注释。代码后用一小段解释为什么这样处理、结果怎样交给下一步、出了问题看什么；不把每行代码重新翻译一遍，也不在每个代码块后机械重复三句问答。

结尾可以停在一次输出、一个对照结果或尚未解决的问题。没有必要再写学习价值、职业前景或鼓励读者的段落。预计收益与实验结果分开，尚未测量的数字不提前填入。

### 配图与篇幅

图用于解释数据去向、状态转移或结果差异。能够用几句话说清的内容不额外画图；必要时一篇保留一两张。采用白底、细边框、深色文字和少量强调色，代码与图里的字段名称保持一致。

篇幅由问题决定。若一篇出现两套独立输入、两个不同失败原因和两套修复，可以考虑拆篇；若拆开后只剩参数罗列，就保留在同一篇。当前 66 篇是编写起点，试写与试读后仍可调整。

### 发表前看一次独立入口

请一位没读过前文的人只拿到本篇与附件，观察他能否说清程序要做什么、找到运行入口、看到预期结果，以及分辨真实调用和测试数据。卡住的地方补背景或材料，不要求他先把整套课程读完。
