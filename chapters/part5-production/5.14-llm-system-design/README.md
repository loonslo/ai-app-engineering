# L5.11 LLM 系统设计 · 清单 + 产物

[全书目录](../../README.md) · [上一章 L5.10](../5.13-managed-runtime-tradeoffs/README.md) · [下一章 L5.12](../../part6-model-tradeoffs/6.1-choose-prompt-rag-finetune/README.md)

- **目标**：掌握一套面试和工作里都能用的 LLM 系统设计答题框架，并按模板写出两份完整设计。
- **v3 路径**：L5.11 / 核心（清单验收）
- **岗位任务 / 面试题型**：T5、T6 / F3
- **前置**：L5 全部前序章节（尤其 5.9 可观测性、5.10 控制面与执行面、5.12 容量与 SLO、5.15 认证与多租户），L4 的 Agent 与工具设计。
- **环境**：纸面练习，不需要账号、不调用模型。
- **时间盒**：3 小时（0.5h 读 + 2h 写两份设计 + 0.5h 自评）。

## 问题

系统设计题不是考你背架构图，而是考你能不能在信息不全时：先问清需求，估算量级，做出有理由的取舍，并说明会怎样失败、怎样验证、怎样回滚。LLM 系统比一般后端多了几个特殊点：质量靠评测而不是单元测试、成本随 token 变化、失败模式更多（幻觉、注入、限流）、权限要落到检索层。

## 概念：答题框架

按这个顺序讲，每一步都要有“结论 + 理由”，不要只列组件：

1. **需求**：用户是谁、核心场景、成功标准、非目标；问清规模、延迟要求、数据敏感度、是否多租户；
2. **容量估算**：请求量（峰值 rps）、每请求 token 数、数据规模（文档数与分块数）；算出模型的 RPM / TPM 需求与大致成本（公式见 [5.12](../5.12-capacity-slo-recovery/README.md)）；
3. **架构（控制面 / 执行面）**：同步请求与异步任务如何分开；哪些放控制面（API、认证、审批入口），哪些放执行面（worker、工具、沙箱）（见 [5.10](../5.10-control-execution-plane/README.md)）；
4. **数据与权限**：数据从哪来、怎么更新、谁能看什么；权限在哪一层强制（检索预过滤，见 [5.15](../5.15-auth-multitenancy/README.md)）；
5. **检索**：切分、召回、重排、引用、拒答；索引更新与版本；
6. **模型与路由**：用哪档模型、什么时候路由到便宜模型、缓存与降级（见 [5.3](../5.3-cost-cache-routing/README.md)）；
7. **评测计划**：用什么数据集、什么指标、什么门槛；上线前和上线后分别怎么评（见 L3）；
8. **成本**：单次请求成本、月成本、成本上限与告警；
9. **失败模式**：限流、超时、幻觉、注入、上游宕机、数据过期；每种怎么发现、怎么降级；
10. **安全**：注入、越权、数据泄露、审计与保留期限（见 [5.7](../5.7-security-guardrails/README.md)）；
11. **上线与回滚**：灰度、指标门禁、回滚步骤、事故演练。

时间有限时，宁可把 2、4、7、9 讲透，也不要平均用力。

## 流程

1. 读本页框架与两个模板（[design-doc](templates/design-doc.md)、[rubric](templates/rubric.md)）；
2. 按设计文档模板写两份设计（见下）；
3. 用评分表给自己打分，并写出最弱的一两项怎么补；
4. 证据写在 [workbook.md](workbook.md)，勾选 [CHECKLIST](gate/CHECKLIST.md)。

## 练习

按 `templates/design-doc.md` 写 2 份设计，每份控制在 3 页以内：

1. **带权限与引用的企业文档问答**：多租户、文档有访问控制、答案必须带引用、更新频繁；
2. **有 3 个内部工具、需要审批的工单 Agent**：例如查工单、改状态、发通知；其中至少一个写操作需要人工审批；要考虑超时、重复提交、可恢复。

## 产物与验收

- 两份填写完整的设计文档；
- 一份自评表（用 `templates/rubric.md`，每个维度写分数和一句证据）；
- 验收看：容量估算有具体数字与公式；权限写清在哪一层强制；评测计划有数据集和门槛；失败模式至少覆盖限流、幻觉、注入、上游宕机，并写明降级方式。

J4（就业轨道的模拟面试）会复用这套模板与评分表。

## 边界

- 纸面设计，没有实现、没有压测、没有评测运行；估算里的数字是你自己的假设，不是实测。
- 评分表是课程自用的练习量表，不是任何公司的面试标准。
- 不覆盖具体云厂商的架构选型细节；产品对比见 [5.13](../5.13-managed-runtime-tradeoffs/README.md)。
