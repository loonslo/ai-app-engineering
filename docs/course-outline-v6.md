# AI 应用与 Agent 开发：用一个报销助手讲清常见工程问题

版本：v6.0 · 独立文章版  
修订日期：2026-11-05  
结构：11 章，55 节；每节对应一篇独立文章。另附项目练习与作者备忘。

这套文章从一张报销单开始。先用 Python 查出记录，再让模型根据资料回答问题。随着功能增加，逐步讨论检索、数据库、审批、权限和服务运行。

报销业务只是共同的例子。读者可以顺着目录做出一个助手，也可以直接阅读自己需要的主题，例如工具调用、文档切分或任务恢复。文章会说明需要哪些基础，并提供本篇的起始材料。

本文是下一轮文章编写的大纲。文中列出的代码包、数据集、演示与验证结果均为待制作内容，不表示已经交付或通过测试。它也不替换仓库当前的课程目录。

## 阅读与发布方式

“章”用于归类，“节”就是发表单位。节内可以有解释、示例和实验，不再把这些小标题当作独立课次。

每篇文章围绕一个主要问题展开。开头用几句话交代当前程序、输入和现象；正文解释相关机制并做一个可观察的改动；结尾停在实验结果、适用条件或尚未处理的情况。没有必要每篇都安排故障，也不要求全部写成同一种七步模板。

独立阅读不等于没有前置知识。数据库文章可以要求读者理解基本 SQL，前端文章可以要求读者会 JavaScript；需要补课时给出相关篇目。运行本篇则不依赖读者手动拼接前几篇代码。

每节的“起始材料”都会作为单独的 starter 包提供，包含本篇所需的完整小程序、合成数据和运行说明。前文链接用于进一步解释，不代替本篇必要的代码与背景。

## 第 1 章：写出第一个能运行的 AI 程序

本章使用终端、编辑器和 Python。首次配置环境的说明放在 1.1 的附件中，其余文章也保留各自的环境检查入口。

### 1.1 在电脑上运行一张报销单

- **问题与内容**：程序怎样显示单号、金额和状态？从运行一个短脚本开始，修改变量，观察保存、工作目录与报错行号。
- **前置与起始材料**：无需编程经验；提供单文件脚本、Windows/macOS 环境说明和预期输出。
- **结果与范围**：重新打开终端后仍能运行，修改状态后输出变化。只介绍本例用到的字符串、变量和打印，不展开完整 Python 语法。

### 1.2 从 JSON 文件里查出一张报销单

- **问题与内容**：记录增加后，怎样按单号查找？用字典、列表、循环和函数读取 JSON，处理不存在的单号，并写出第一条测试断言。
- **前置与起始材料**：会运行脚本；提供三张合成单据、函数骨架和可运行测试示例。
- **结果与范围**：新增记录、打乱顺序后仍能查对，查不到时返回明确空值。只做本地读取，不加入数据库和模型。

### 1.3 发出一个问题，读回模型的回答

- **问题与内容**：Python 程序怎样与模型通信？配置环境变量，发送一条问题，找到响应中的正文、结束状态与用量信息，并观察缺少配置和超时的结果。
- **前置与起始材料**：理解函数和字典；提供调用模板、变量名示例和脱敏响应样本。
- **结果与范围**：有服务访问条件时完成一次真实调用；否则先阅读明确标注的响应样本。字段按本篇选定的接口讲解，不混用不同接口结构，不展开自动重试。

### 1.4 把一次模型响应保存下来，供本地调试使用

- **问题与内容**：同一个问题每次回答不同，测试怎样重复运行？保存请求特征与脱敏响应，以匹配请求的方式回放，区分录制数据与人工测试替身。
- **前置与起始材料**：理解请求和响应；提供完整小客户端、已录制样本和模拟异常。
- **结果与范围**：相同测试输入得到固定结果，未录制输入明确报错。回放用于验证程序分支，不能证明真实模型回答质量，也不默认把未匹配请求转成付费调用。

## 第 2 章：让助手查资料、调用工具

本章先使用少量 JSON 资料。这样可以直接看见程序查到了什么，再观察模型怎样使用这些结果。

### 2.1 先查制度，再让模型回答

- **问题与内容**：模型不知道公司的报销制度时，程序可以提供哪些依据？按条款号或限定关键词找出原文，再拼成回答上下文。
- **前置与起始材料**：会调用模型、读取 JSON；提供四条制度、查询函数和回答模板。
- **结果与范围**：回答带可定位的条款标识，原文由程序读取；无匹配时明确说明缺少依据。修改制度后重新运行比较结果，不预设模型一定会编造答案。向量检索留到第 5 章。

### 2.2 模型提出工具调用后，Python 怎样执行

- **问题与内容**：模型返回工具名和参数后会发生什么？依次查看工具说明、参数校验、本地函数执行、结果回填和最终回答。
- **前置与起始材料**：理解函数调用与模型消息；提供一个查单工具、两次模型响应及完整调度骨架。
- **结果与范围**：能对应每一步的输入与输出；未知工具和非法参数被程序拒绝。只处理一个只读工具，不加入多工具规划。

### 2.3 查完单据，再根据需要查制度

- **问题与内容**：一个问题需要两份资料时，助手怎样继续查？注册查单据和查制度两个工具，分别观察一步查询、两步查询和资料不全的情况。
- **前置与起始材料**：理解工具结果回填；提供双工具程序、单据与制度数据、三组回放。
- **结果与范围**：保留本轮实际取回的证据；只找到退回备注时不补写不存在的制度。缺参追问与会话保存单独在 2.4 讨论。

### 2.4 用户补充一个单号后，怎样接着上一轮回答

- **问题与内容**：用户先问“为什么退回”，随后补充单号，程序怎样关联两轮输入？保存消息历史，明确会话标识、缺参追问和清空会话的行为。
- **前置与起始材料**：理解模型消息与工具；提供两个测试会话和已接好的双工具助手。
- **结果与范围**：补充单号后继续查询，不同会话互不混用。演示超长历史的明确截断或提示策略，不把整个历史无限追加，也不实现长期记忆。

### 2.5 给工具调用循环设置结束条件

- **问题与内容**：助手一直查询或等待接口时，程序怎样结束？设置总步数、请求超时和重复无进展检测，给每种终止原因单独记录状态。
- **前置与起始材料**：会读循环与异常处理；提供正常、重复调用和超时三组响应序列。
- **结果与范围**：成功、超限与超时均有明确出口。相同参数不自动等于错误；示例结合结果是否变化判断无进展，不把这里的阈值当成所有业务的通用配置。

### 2.6 回答错了，先沿着运行记录看一遍

- **问题与内容**：引用错条款时，怎样分清查错记录、传错参数和生成错误？把一次执行记录成请求、工具调用、返回证据与结束原因。
- **前置与起始材料**：理解双工具执行；提供三份脱敏失败记录和最小日志器。
- **结果与范围**：为每个例子指出第一次偏离预期的位置，并验证一处针对性修复。只做本地排查，不要求先搭追踪平台；样本统计在第 10 章展开。

## 第 3 章：把模型接进一个具体功能

本章把已能调用的函数放进网页和业务流程。每篇都带自己的调用替身，页面和数据校验可以先在本地调试。

### 3.1 给查询助手加一个本地网页

- **问题与内容**：怎样让别人不用终端也能提问？用 FastAPI 和原生 HTML/JavaScript 接入一个现成的问答函数，展示回答、原文、等待和错误状态。
- **前置与起始材料**：会调用 Python 函数；提供可运行网页模板和固定响应替身，并解释本例涉及的 HTTP 请求。
- **结果与范围**：正常、空输入和服务错误均有页面反馈。本篇只在本机运行，不加入登录、React 和流式传输。

### 3.2 从票据文本里抽取固定字段

- **问题与内容**：怎样把一段票据文本整理成程序可处理的数据？定义字段、类型和缺失表示，使用所选模型支持的结构化输出方式，并在本地解析校验。
- **前置与起始材料**：理解字典与模型调用；提供合成 OCR 文本、字段定义和包含拒绝或不完整响应的样本。
- **结果与范围**：返回候选单据或明确失败状态。结构符合要求并不表示内容真实；金额关系在 3.3 校验，OCR 本身不在本篇实现。

### 3.3 字段都齐了，金额为什么还是对不上

- **问题与内容**：明细、总额、币种之间怎样校验？使用 Decimal 处理金额，写出字段间的业务规则，把原始票据矛盾与可修正的格式错误分别处理。
- **前置与起始材料**：理解结构化记录；提供候选单据、Pydantic 校验骨架和合成异常样本。
- **结果与范围**：合计不符、负金额和币种不一致进入明确错误或人工复核分支，不让模型改数字凑总额。只验证给定规则，不证明票据真实性。

### 3.4 报销初审步骤固定时，直接写一个 Workflow

- **问题与内容**：已知要检查格式、分类和资料完整性时，怎样组织流程？用普通函数描述串行步骤、条件分支和中止原因，再与工具循环处理同一任务作比较。
- **前置与起始材料**：会写函数和条件判断；提供相同输入集、检查函数与 Agent 对照程序。
- **结果与范围**：列出路径、调用次数和错误样例；真实耗时与费用另行实测。对照结果不预填，不把固定流程强行改造成动态 Agent。

### 3.5 批量检查时，怎样限制同时发出的请求

- **问题与内容**：多个外部检查可以并行时，怎样避免阻塞或发出过多请求？比较串行与异步调用，加入并发上限、超时和单项失败结果。
- **前置与起始材料**：理解函数与异常；提供模拟延迟接口、批量输入和逐步解释的异步骨架。
- **结果与范围**：观察实际最大并发数及失败项，其他任务按既定策略完成或取消。模拟延迟只说明调度行为，不作为真实模型加速数据；网页停止操作在 9.2 讨论。

## 第 4 章：保存数据，识别用户，限制操作

数据库起点采用 PostgreSQL，以便后面的事务和检索文章共用数据格式。每篇提供本地启动配置、建表与种子数据，不要求读者先搭完全部服务。

### 4.1 把 JSON 报销单存进数据库

- **问题与内容**：记录怎样在程序重启后继续查询？介绍本例需要的表、主键、字段、连接和查询，把合成 JSON 导入 PostgreSQL。
- **前置与起始材料**：理解字典和查询函数；提供数据库启动配置、初始化脚本与 SQLAlchemy 查询骨架。
- **结果与范围**：导入后按单号查找，重新启动仍能读到记录。解释初始化与后续结构迁移的区别，不同时展开复杂 ORM 设计。

### 4.2 保存单据成功，写审计记录失败，怎样一起回滚

- **问题与内容**：一次业务操作写入多张表时，哪些操作应共同成功？在事务中保存单据和审计记录，观察中间步骤失败后的数据。
- **前置与起始材料**：理解基本插入与查询；提供已建表的小服务和可触发失败的审计写入函数。
- **结果与范围**：成功时两份记录都在，失败时均不提交。事务范围限于本地数据库，不把外部模型或付款请求当作可一并回滚的数据库操作。

### 4.3 两个人同时提交报销，预算怎样扣才不会超额

- **问题与内容**：先查余额再扣减会怎样竞争？用两个并发请求复现，再比较条件更新与行锁两种实现。
- **前置与起始材料**：理解事务；提供预算表、同步起跑的并发测试与固定金额样例。
- **结果与范围**：按初始预算和申请金额计算预期成功数，核对余额、单据与审计记录。使用真实本地数据库验证竞争，不用内存替身证明数据库锁有效。

### 4.4 登录之后，后端怎样知道当前用户是谁

- **问题与内容**：请求里携带的信息怎样成为可信身份？借助已配置的本地 OIDC 身份服务和登录模板，查看登录结果、会话建立及后端身份上下文。
- **前置与起始材料**：理解请求与响应；提供本地测试账号、登录模板和无效凭据样本。
- **结果与范围**：有效登录形成服务端身份，伪造和过期凭据被拒绝。区别登录身份与 API 访问凭据；本篇不自建身份提供方，也不把登录成功等同于拥有审批权限。

### 4.5 同样登录成功，为什么不能查看别人的报销单

- **问题与内容**：用户身份确定后，怎样判断能否访问某条记录？围绕租户、记录归属与审批职责实施资源授权，将检查放在服务端业务入口。
- **前置与起始材料**：理解身份上下文；提供已接登录的服务、两租户数据和员工/主管测试身份。
- **结果与范围**：查询与修改均覆盖跨租户、同租户不同归属、额度不足等场景。离线身份替身与真实登录验证分别报告；数据库 RLS 可作为扩展实验，不与本篇同时起步。

## 第 5 章：让问答助手查到合适的资料

每篇保留文档来源和片段标识。解析、切分、召回、重排、上下文与生成分别观察；检索改善与回答改善分别记录。

### 5.1 PDF 提取出的文字，为什么会丢失表格含义

- **问题与内容**：原文看得懂，提取结果为什么读不通？检查文本顺序、页码、表头与跨页表格，输出保留来源的规范化内容。
- **前置与起始材料**：会读取文件；提供自制 PDF、可运行提取脚本和人工核对文本。
- **结果与范围**：逐项比较提取内容与原页，标记无法可靠解析的部分。主例只处理文本型 PDF；扫描件 OCR 作为额外条件说明，不承诺一种方案处理所有版式。

### 5.2 文档应该在哪里切开：按长度切分与按标题切分

- **问题与内容**：一条制度被切成两半后还剩多少含义？比较两种切分方式，保留标题、条款号、表头和必要的重叠内容。
- **前置与起始材料**：会处理字符串；提供规范化 Markdown、两种切分器和固定查询样本。
- **结果与范围**：检查片段是否可读，并比较关键依据是否完整落在候选片段中。给出片段 ID 与来源映射，不在本篇调优重排模型。

### 5.3 关键词不同，怎样找到意思相近的条款

- **问题与内容**：问题写“打车”，条款写“市内交通”，怎样比较语义？对准备好的片段做向量化，写入 pgvector，再查看相似度排序。
- **前置与起始材料**：理解数据库查询；提供预切分资料、数据库配置、固定向量样本及真实嵌入调用入口。
- **结果与范围**：分别运行语义相近与无关问题，观察候选结果。固定向量只用于程序测试；真实召回效果需要实际嵌入模型。相似度高不直接代表足以回答。

### 5.4 条款编号与自然语言问题，怎样一起检索

- **问题与内容**：编号查询与语义查询需要不同信号时，怎样合并结果？先分别查看编号/关键词与向量候选，再用 RRF 融合排名。
- **前置与起始材料**：理解候选列表；提供两路检索器、中文分词配置和包含精确编号的查询集。
- **结果与范围**：比较各路与融合后的命中情况，保留失败样例。编号可独立精确匹配；中文分词需单独检查，不把默认全文检索当作现成中文方案，也不把 RRF 称为语义重排模型。

### 5.5 找到了相关片段，为什么仍然没有排到前面

- **问题与内容**：正确片段已经在候选集中，怎样改善排序？接入一个重排器，比较重排前后的位置与耗时。
- **前置与起始材料**：理解召回与排序的区别；提供冻结的候选列表、相关性标注和重排调用入口。
- **结果与范围**：报告排序改善、退化和耗时；单列候选中根本没有答案的情况。回放可验证排序代码，真实重排质量另测；本篇不扩大召回范围掩盖排序问题。

### 5.6 检索结果怎样交给模型：去重、长度限制与引用

- **问题与内容**：取回的资料怎样组成可用上下文？处理重复片段、低相关结果和长度预算，把可引用的来源映射交给回答程序。
- **前置与起始材料**：理解检索结果与模型调用；提供重复、过长、无关及空结果四类输入。
- **结果与范围**：上下文长度有界，引用能定位原文，资料不足时明确说明。引用存在与回答受到原文支持分别检查；本篇不通过添加无关片段来凑足候选数。

### 5.7 制度更新后，怎样避免继续引用旧版本

- **问题与内容**：同一份制度换了内容，索引怎样跟着更新？记录文档版本、内容摘要与有效状态，完成增量导入和旧版本失效。
- **前置与起始材料**：理解检索表与事务；提供两版合成制度、已有索引和更新脚本。
- **结果与范围**：重复导入不产生重复片段，新查询只使用当前有效版本，旧引用按明确规则提示失效或查看获准历史版本。用户撤权与答案缓存放在 7.2。

## 第 7 章：处理受限资料与不可信输入

本章分别观察“可以检索什么”“已经生成的内容还能否查看”与“资料里的指令是否被执行”。测试覆盖具体路径，不用一组样例宣称系统能防住所有攻击。

### 7.1 不同员工提同一个问题，怎样只检索各自能看的资料

- **问题与内容**：权限怎样参与候选资料选择？使用服务端身份限定文档范围，在检索请求中携带授权条件，并检查候选集与模型上下文。
- **前置与起始材料**：理解资源授权与向量检索；提供两租户、不同角色的制度及已有检索服务。
- **结果与范围**：未授权资料不进入生成上下文；分别测授权正确性和过滤后的召回数量。SQL 权限条件与近似索引内部扫描顺序不是一回事，不能据此宣称索引只扫描获准向量。

### 7.2 权限撤销后，缓存答案和历史引用怎样处理

- **问题与内容**：用户曾经有权查看，后来调岗，旧内容如何再次访问？在缓存中区分用户与权限版本，查看历史回答和原文时使用当前权限检查。
- **前置与起始材料**：理解授权检索；提供含来源依赖的缓存答案、历史记录和可变权限服务。
- **结果与范围**：测试撤权后命中缓存、打开旧回答及点击引用三条路径。服务端阻止后续返回，不能撤回用户已下载或已看到的副本；文档版本失效与权限失效分开记录。

### 7.3 单据备注里出现“忽略规则”，程序会怎样处理

- **问题与内容**：资料可能包含要求模型改变行为的文字，怎样观察影响并限制动作？把资料视为待分析输入，同时在执行端验证工具权限、参数归属和批准记录。
- **前置与起始材料**：理解工具调用与审批；提供合成恶意备注、只读和受保护的模拟写工具。
- **结果与范围**：即使模型提出越权写操作，执行端也拒绝；记录错误回答是否仍会发生。测试包含同一工具的越权参数，不只检查不存在的工具名。提示词约束作为辅助，不当作授权机制。

- **结果与范围**：比较成功与失败样例、耗时和用量，检查敏感上下文是否被多传。只选一种协作方式，不同时讲完所有多 Agent 模式；没有测得收益时保留简单实现。

## 第 9 章：显示执行过程，继续未完成的任务

## 第 10 章：判断一次修改是否有效

每篇都提供自己的输入集，因此可以在对应功能完成后提前阅读。离线测试验证确定性行为，真实模型实验观察回答与决策质量；两类结果分开报告。

### 10.1 把几次错误回答整理成一个可重复使用的样本集

- **问题与内容**：零散问题怎样留下来供下次比较？从运行记录提取输入、资料版本、期望行为和失败位置，区分修复样本与保留评测样本。
- **前置与起始材料**：会读工具与检索记录；提供少量合成成功/失败样本及标注表。
- **结果与范围**：每条样本可追溯，争议样本单列，正常与资料不足场景都保留。先整理具体错误，不设一个无法解释的总分，也不在看过评测结果后随意改标准答案。

### 10.2 检索改得有没有用：看候选结果，也看漏掉的资料

- **问题与内容**：更换切分或检索方式后，怎样比较？用同一相关性标注集计算 Hit@K、Recall@K，并逐条查看退化样本。
- **前置与起始材料**：理解检索候选；提供冻结查询集、相关片段集合及两组检索结果。
- **结果与范围**：写清分母、K 和无答案样本的处理方法。检索指标不代替回答质量；没有完整相关性标注时，不把局部命中统计冒称完整召回率。

### 10.3 最终答案看起来对，工具调用过程也对吗

- **问题与内容**：过程里越权、漏校验或重复写入，怎样被测试发现？针对工具轨迹检查参数归属、必要授权和写操作次数。
- **前置与起始材料**：理解工具记录与业务权限；提供答案相近但路径不同的执行样本。
- **结果与范围**：能拦截结果正确但过程违规的例子。固定业务约束才检查固定顺序；对允许多种正确路径的任务，不强求逐步复制参考轨迹。

### 10.4 请另一个模型评回答，怎样知道它评得是否可靠

- **问题与内容**：模型给出的“通过”能否作为依据？选择一个清楚的问题，例如回答是否受到资料支持，写判定说明，再与人工标注比较。
- **前置与起始材料**：理解评测样本；提供人工标注集、模型判定入口和分歧记录。
- **结果与范围**：先定义正类含义，再查看混淆矩阵、误判和漏判；保留独立校准/评测划分。裁判失败或无法判断单列，不悄悄当作通过，不用模型判分替代权限断言。

### 10.5 改完提示词或代码，哪些检查放进持续集成

- **问题与内容**：怎样在下一次修改时发现退化？将确定性测试、固定响应回归和真实模型评测分开运行，保存配置、版本与结果差异。
- **前置与起始材料**：理解 pytest 和基本评测；提供小项目、离线样本集与 CI 配置示例。
- **结果与范围**：故意引入一个确定性错误时检查失败；真实模型结果按约定样本与统计方式比较。首次安装依赖、下载模型和准备数据库需要单列，不把预备环境下的离线运行写成从零全程断网。

## 第 11 章：观察服务，并把它交给别人运行

这一章关注已运行的程序。文章里的性能、成本和稳定性结论只对应明确写出的样本、配置和环境。

### 11.1 一次回答很慢，时间花在了哪里

- **问题与内容**：检索、重排、等待模型与工具执行各耗时多少？为一次请求建立关联标识和分段耗时，使用 OpenTelemetry 展示父子调用关系。
- **前置与起始材料**：理解问答调用链；提供可调延迟的小服务与控制台追踪输出。
- **结果与范围**：能定位人为加入的延迟，区分首段响应时间与整体完成时间。模拟耗时用于验证记录方式，接入外部追踪平台作为可选附件。

### 11.2 记录问题时，怎样避免把原始票据和凭据一起写进日志

- **问题与内容**：排查所需信息与不宜保存的内容怎样分开？用允许字段清单记录事件，为异常、嵌套参数和外部错误响应补脱敏处理。
- **前置与起始材料**：理解结构化日志；提供合成敏感字符串、样本异常和日志处理器。
- **结果与范围**：在正常与失败输出中搜索测试标记，检查请求标识和错误类型是否仍足够排查。样例通过只证明所测路径，不声称能自动识别所有个人信息。

### 11.3 一次回答用了多少资源，哪些成本可以减少

- **问题与内容**：怎样把调用次数、输入输出用量与成本关联起来？按请求汇总已报告用量，区分缓存命中、工具循环、重试和缺失统计。
- **前置与起始材料**：理解模型响应与运行记录；提供脱敏用量样本、带日期的计价配置和对照输入。
- **结果与范围**：比较一次受控改动前后的用量与回答质量。未知用量标为未知，估算费用注明价格日期；不把供应商提示词缓存与应用答案缓存混为一谈。

### 11.4 主模型暂时不可用时，怎样重试或切换

- **问题与内容**：服务报错后继续等待、重试还是降级？按失败类型安排次数和时间预算，检查备用服务支持的结构化字段与工具能力。
- **前置与起始材料**：理解超时与工具调用；提供两种模型适配器替身和可控失败序列。
- **结果与范围**：重试有上限，能力不匹配时明确失败或转人工；授权检查保持一致。真实供应商兼容性单独验证，业务写操作不随模型重试无条件重做。

### 11.5 把项目交给另一台电脑运行

- **问题与内容**：项目离开自己的开发环境后需要哪些材料？整理依赖锁定、环境变量说明、数据库初始化、离线演示、启动与停止方式。
- **前置与起始材料**：会运行服务；提供独立的小项目快照与待补充的 README，不要求完成全部 55 篇。
- **结果与范围**：在干净目录或另一台机器按说明运行，记录环境、步骤与实际失败点，完成一条问答或审批演示。本篇验证交付可用性，不将本地启动写成生产容量、可用性或真实用户验收。

## 附录 B：给作者的简短备忘

### 一篇文章的准备材料

每篇开始写之前，先确定标题、读者需要的基础、本篇输入、起始代码和可观察结果。上述逐节条目是写作任务书；正式文章发布时，可以把这些内容自然放进开头与运行说明，不必原样贴出三项清单。

起始包与参考实现分别保存。故障版本只在确实能帮助解释时提供；不为每篇强行建立四个分支。包内列出依赖版本、运行命令、数据来源、样例输出和测试入口。共用函数可以来自仓库，但单独下载的包中也包含所需内容。

涉及模型时，区分三种结果：真实调用、录制回放、人工测试替身。回放按请求匹配，数据经过脱敏。可以先运行离线样例；调用真实服务所需的环境与费用条件在入口处说明。

### 文字怎样写得自然

开头从一个具体情形写起。例如：

> 报销单保存成功后，程序还要写一条审计记录。如果第二次写入失败，数据库里会留下什么？这一篇用两张表和一个主动抛出的异常，看看事务提交前后发生了什么。

这样的开头已经交代了对象、问题和接下来的操作。不需要先批评初学者的习惯，也不需要说明读者“只有理解这个才算真正入门”。

标题可以混合使用问题与陈述，不必 55 篇都写成“为什么”。正文少用“必须牢记”“正确姿势”“核心铁律”等命令式措辞。涉及安全或数据一致性时，把约束和后果直接写出来，例如“这次批准只对应版本 3，版本变化后需要重新确认”。

代码的关键位置写简短中文注释。代码后用一小段解释为什么这样处理、结果怎样交给下一步、出了问题看什么；不把每行代码重新翻译一遍，也不在每个代码块后机械重复三句问答。

结尾可以停在一次输出、一个对照结果或尚未解决的问题。没有必要再写学习价值、职业前景或鼓励读者的段落。预计收益与实验结果分开，尚未测量的数字不提前填入。

### 配图与篇幅

图用于解释数据去向、状态转移或结果差异。能够用几句话说清的内容不额外画图；必要时一篇保留一两张。采用白底、细边框、深色文字和少量强调色，代码与图里的字段名称保持一致。

篇幅由问题决定。若一篇出现两套独立输入、两个不同失败原因和两套修复，可以考虑拆篇；若拆开后只剩参数罗列，就保留在同一篇。当前 55 篇是编写起点，试写与试读后仍可调整。

### 发表前看一次独立入口

请一位没读过前文的人只拿到本篇与附件，观察他能否说清程序要做什么、找到运行入口、看到预期结果，以及分辨真实调用和测试数据。卡住的地方补背景或材料，不要求他先把整套课程读完。

### 影响文章边界的技术依据

以下页面于 2026-11-05 读取，用于本轮大纲的少数边界核对，不代表 55 篇的配套实现已完成验证。正式写代码时再记录实际使用的依赖版本与协议版本。

- **3.3 字段间校验**：Pydantic 提供模型级校验器，可用于表达字段之间的关系；本例具体金额规则由业务定义。[Pydantic Validators](https://pydantic.dev/docs/validation/latest/concepts/validators/)
- **4.4 身份基础**：OIDC 区分身份认证与 OAuth 访问授权；文章分别说明登录身份和 API 凭据的用途。[OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html)
- **5.4 全文检索**：PostgreSQL 的文本搜索配置、解析与排序需要分别说明；`ts_rank_cd` 使用覆盖密度排序，不作为 BM25 的别名。[PostgreSQL 文本搜索控制](https://www.postgresql.org/docs/current/textsearch-controls.html)
- **6.2 状态持久化**：检查点保存线程范围内的图状态；内存检查点不提供进程重启后的持久化。[LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)
- **6.3 审批恢复**：恢复 interrupt 所在节点时会重新执行该节点开头的代码，因此 6.4 单独讲等待前保存提案。[LangGraph Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)
- **7.1 过滤与索引**：pgvector 的近似索引扫描与过滤可能造成返回候选不足，需要实际检查查询结果与扫描策略。[pgvector Filtering](https://github.com/pgvector/pgvector#filtering)
- **8.2 远程授权**：本次核对的 MCP 授权页为 2026-07-28 版本，说明 HTTP 传输的授权流程；不将相同流程套用于本地 stdio。[MCP Authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)
- **9.1 与 9.5 事件流**：SSE 的事件、数据、ID 与重连机制需要和客户端接收方式一起解释。[MDN：使用服务器发送事件](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)
