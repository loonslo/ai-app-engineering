# P2 最小上线 · 项目章

[全书目录](../../README.md) · [上一章 P1](../11.1-requirements-metrics/README.md) · [篇首](../README.md) · [下一章 P3](../11.3-control-plane-hardening/README.md)

- **目标**：在第 6 周末前把“知识库 v1 + 嵌入式功能”最小上线到公网，邀请真实用户，开始积累真实用量。
- **v3 路径**：P2 / 项目（清单验收）
- **岗位任务 / 面试题型**：T5、T6 / F4
- **节奏**：5 小时，第 6 周末前完成。
- **前置**：L1.10（嵌入式 LLM 功能）、L2.12（知识库 v1）、[11.1](../11.1-requirements-metrics/README.md)。
- **环境**：**需要 VPS 或云账号，可能产生费用**。没有账号时只能完成纸面部分，并把实操项如实标为“未完成”。

## 为什么

要拿到“公网可访问且已运行 ≥4 周、有真实用户与真实请求”这样的证据，唯一的办法是**尽早上线、让它持续运行**：用量需要时间积累，晚一周上线就少一周数据。所以第一版要“最小”，不要等到做完美。

## 最小上线包含什么

- 知识库 v1（L2.12）加嵌入式功能（L1.10）；
- **HTTPS**；
- **简单鉴权**（API key 或基础认证）；
- **不含个人信息的请求日志**：记 trace_id、耗时、token、状态；不记原始提问里的手机号、邮箱等（可复用 [5.7 的脱敏](../../part5-production/5.7-security-guardrails/README.md)）；
- **费用上限**：在模型厂商控制台与云平台两处设上限或预算告警；
- **用户反馈入口**：哪怕只是“有用 / 没用”两个按钮或一个表单。

## 不包含什么

高可用、多租户、执行面。这些留给后续迭代（[11.3](../11.3-control-plane-hardening/README.md)、[11.4](../11.4-execution-plane-launch/README.md)）。

## 部署方式

- **一台 VPS 加 Docker Compose**：最便宜、最通用的方案，更新和加固要自己做；
- **托管服务**：可以用 [5.11 云部署](../../part5-production/5.11-cloud-deploy/README.md)介绍的托管容器服务。那一章你届时可能尚未学到，按其 README 和清单操作即可。

## 步骤

1. 把现有 RAG + 嵌入式功能封装成 FastAPI 服务（见 [5.1](../../part5-production/5.1-serve-fastapi/README.md)），本地跑通；
2. 加鉴权、脱敏日志、费用上限；
3. 部署到 VPS 或托管服务，配 HTTPS；
4. 访问验证，填 [部署记录](templates/deploy-record.md)；
5. 邀请至少 3 位真实用户（来自 11.1 的访谈对象更好），告诉他们这是早期版本；
6. 每周记录一次请求数与反馈（[反馈日志](templates/feedback-log.md)）。请求数要**区分自测与真实用户**。

## 模板

- [`templates/deploy-record.md`](templates/deploy-record.md)
- [`templates/feedback-log.md`](templates/feedback-log.md)

## 产物与验收

见 [CHECKLIST](gate/CHECKLIST.md)。验收看：能不能从外网访问（可以只记私有地址，但要说明谁能访问）；日志里有没有个人信息；费用上限是否真的设置；请求计数方式能否区分自测与真实用户。

## 常见失败

- 等“做完整再上线”，错过积累用量的时间；
- 日志里把用户的原始提问连同手机号一起存了；
- 没设费用上限，被刷或跑飞后账单失控；
- 请求计数把自己的测试算进真实请求。

## 边界

- 这只是最小可用，**不代表生产级安全**：没有多租户隔离、没有速率限制的完整方案、没有高可用。
- 本章没有可执行检查，也不替你部署；课程没有提供任何“已上线”的证据。
